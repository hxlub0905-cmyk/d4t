# 怎麼用 Focus index 這張卡，以及怎麼跟機台的 F.I. 對齊

> **d4t — defect**　·　Measure 段的 `Focus index`（`focus_quality`）
> 這一份是**給使用者的操作手冊**：四個數字各是什麼、哪一個在哪一種區域上
> 靠得住、以及怎麼把它換算成機台自己的 F.I.。演算法的來龍去脈在
> [`d4t/core/algo/iqi.py`](../d4t/core/algo/iqi.py) 的模組說明，那一份不必讀。

---

## 0. 這一份裡的數字是哪裡來的（先讀這一段）

**2026-09-18，一次廠外驗證。** 兩批真實機台檔（共 23 張），每一張帶著**機台
自己算的 F.I.** 當真值；跑的是 d4t 的 CLI 加 headless 的 cv2。

* **機台 A** —— 高密度重複圖案（array）區。3584 × 3584、u16、10 張，
  真值落在 0.487–0.539。
* **機台 B** —— logic（不重複）區。7680 × 7680、u16、13 張，
  真值落在 0.254–0.390。

> ⚠ **機台代號與 lot 名稱一律遮蔽**（`CLAUDE.md` 鐵則 8），所以這一份從頭到尾
> 只有「機台 A」與「機台 B」。

⚠ **這一份裡的每一個相關係數都是「量到的事實」，不是這個 repo 算得出來的
東西。** 那些影像不能進 repo，所以：

* **數字一律照抄**，不要四捨五入、不要「順手改好看一點」；
* **測試裡一個都不會出現** —— `tests/test_iqi.py` 最後一節斷言的是**形狀**
  （合成資料，`tests/iqi_fixtures.py`）；
* **要重驗只有資料的擁有者做得到。** 看到一個覺得低的數字，先讀 §4 再說 ——
  低不代表算錯。

## 1. 四個數字，以及它們在哪一種區域上靠得住

在卡片最上面那一排 **`Sharpness numbers`** 勾選。前三個是快的整張圖量法，
`focus_iqi` 是 OP-301 那一套（切 64 塊、去背景、取前 30% 平均），
**勾了才算** —— 它一顆要做 64 次 FFT。

對機台 F.I. 的 Pearson r（廠外實測，2026-09-18）：

| 勾這個 | 機台 B（logic） | 機台 A（array） |
|---|---|---|
| `focus_iqi`（OP-301）| **0.959** | ≤ 0.444 |
| `focus_lapvar`（Laplacian 變異數）| 0.951 | ≤ 0.444 |
| `focus_fft`（高頻能量佔比）| 0.919 | ≤ 0.444 |
| `focus_tenengrad`（平均梯度能量）| 0.918 | ≤ 0.444 |

兩件事一眼看得出來：

1. **在 logic 區，四個都好，IQI 最好。** 差距（0.918 → 0.959）比它們之間的
   複雜度差距小得多 —— 挑哪一個不是這裡最重要的決定。
2. **在 array 區，四個都不行。** 而且 §4 會說明：**沒有一組參數救得回來**。

**比「挑哪個指標」更要緊的是 §3 那件事（16 → 8 bit 怎麼降）。**
同一個 `focus_tenengrad`，在機台 B 上正確的降位法給 0.92，換成逐張拉伸給
**0.008** —— 指標沒變，答案垮了。

## 2. `Measure on`：量亮度，還是量邊（F115）

`focus_iqi` 勾起來之後，**進階**區會多一格 `Measure on`：

| 選項 | 意思 | 什麼時候用 |
|---|---|---|
| **`The image`**（預設）| 四個步驟跑在影像的灰階上。**逐位元組就是 OP-301 寫的那一套**，今天以前存下來的每一份 recipe 都是這個。 | 預設；logic 區 |
| **`Its edges`** | 先把影像換成邊的強度（梯度），**同樣那四個步驟一個字都不改**地跑在上面。 | 重複 array 區，灰階那條路量不出東西的時候 |

**它問的是你的樣品，不是問軟體要用哪個公式** —— 所以它是一格參數（一條岔路），
不是一個 `method`（`CLAUDE.md` §3）。

廠外實測：

* 機台 A（array）：0.31 → **0.49**。那是那台機台上量到的**局部最好**。
* 機台 B（logic）：0.9593 → **0.9596**。也就是**沒有變差**。

> ⚠ **0.49 不是一個可以出貨的相關。** 這一格是 array 區的一個**起點**，
> 不是終點 —— 真正的問題在 §5。
>
> ⚠ **廠外那兩個數字跟出貨的這條路不是同一個算法。** 廠外量的是兩個變體
> （機台 A 那個是**不切塊**的整張圖梯度帶通；機台 B 那個是 Gx 與 Gy **分開**
> 帶通再把能量相加）。出貨的是 `iqi.py` 模組說明寫的那一條：先合成
> `G = √(Gx² + Gy²)`，再原封不動地跑那四個步驟。所以**出貨這條路在真資料上的
> 相關係數還沒有人量過** —— 上面兩個數字是「這個方向值得走」的證據，不是
> 它的成績單。

## 3. 16-bit 的圖怎麼降成 8-bit：**這是一格站點參數**

整條 pipeline 是 8-bit 的，而機台出的是 u16。降位法有兩種，**選錯比選錯指標
貴得多**：

| 做法 | 在哪 | 什麼時候對 |
|---|---|---|
| **取高 8 位**（右移）| 載入的當下，`rawfile.suggest_shift` 量第一張的實際最大值決定一次，**整批共用** | 資料用滿（或接近用滿）16-bit 的動態範圍時 |
| **逐張 p1–p99 拉伸** | 影像段的 `Normalize` 卡（`percentile`）| 資料只用到動態範圍的一小段時 |

廠外實測，兩台機台的答案**相反**：

* **機台 B**：取高 8 位 **r = 0.96**，逐張 min-max 拉伸 **0.78**。取高位贏。
* **機台 A**：像素值只落在 14k–65k（**16-bit 滿量程的 77%**），取高 8 位把
  對比壓成一條窄帶 → **r = 0.03**；換成逐張 p1–p99 拉伸才回到 **0.31**。

⚠ **拉伸有代價，而那個代價是這個工具的全部**：逐張各自拉伸之後兩張圖之間
不再可比。要拉就用 `Normalize` 卡的 **`Borrow range from`**，讓整批共用同一個
範圍 —— 不然你量到的是「這張圖自己的對比」，不是「這張圖清不清楚」。

**怎麼決定**：量一次那批資料的 p1 與 p99。貼著滿量程 → 取高位；縮在一小段 →
拉伸。這一段在 [`PITFALLS.md`](PITFALLS.md) 也有一列（症狀那一面）。

## 4. 跟機台的 F.I. 對齊（校正）

d4t 的 `focus_iqi` 跟機台的 F.I. **量的是同一件事，但不是同一把尺**：
一個是平均能量（幾百到幾千），一個是 0–1 的指數。對齊要做的只有一件事 ——
**一條直線**。

### 4.1 步驟

1. **收一批真值。** 同一批影像，每一張記下機台給的 F.I.。十幾張就夠
   （廠外那兩批分別是 10 張與 13 張）。
2. **跑一次 d4t**，讓 `focus_iqi` 寫進 `defects.csv`（`Write report` 卡，
   `What to put in the folder` 勾 `table`）。
3. **最小平方擬合 `GT = a × FI + b`。** Excel 的 `SLOPE()` / `INTERCEPT()`
   就夠了，兩欄各十幾格。
4. **把 `a` 與 `b` 寫進判定段。** ⚠ **不必加任何一張卡** —— 判定面板的
   **`Working numbers`** 那一列加一行就是了：

   ```
   fi_cal = 0.001146 * focus_iqi - 0.1790
   ```

   然後判定樹拿 `fi_cal` 去比（例：`fi_cal < 0.30`）。分數表達式本來就吃
   乘法、加減與數字常數，這一行不是新功能。

### 4.2 兩組量到的常數（**照抄用的例子，不是預設值**）

| | `a` | `b` | 對得多準 |
|---|---|---|---|
| **機台 B**（logic）| `0.001146` | `-0.1790` | 殘差標準差 **0.0115** ＝ 真值跨距的 **8.4%**；最差的那一張差 **0.0184** |
| **機台 A**（array）| `0.000394` | `-0.3976` | 在它最好的那一組 OP-301 設定上，而那一組本身 r 只有 0.31 |

### 4.3 ⚠ **常數與設定都不跨機台、不跨區域**

**把機台 B 的設定與這兩個常數原封不動套到機台 A，量到的 r 是 0.03。**

那不是「差一點」，是**完全沒有關係**。所以：

* **每一台機台、每一種區域各校一次**，校出來的兩個數字寫進**那一份 recipe**
  （`CLAUDE.md` 的最高指導原則：站點差異封裝進 recipe，不封裝進程式碼）；
* 換了區域、換了倍率、換了影像處理鏈 → **重校**；
* 上面那張表是**格式的範例**，不是可以拿來用的值。

## 5. array 區為什麼救不回來（以及還沒問到的那一句話）

機台 A 上量過的**每一種**方法（2026-09-18）：

| 方法 | r |
|---|---|
| 整份 OP-301 參數網格（4 種縮放 × 4 種降位 × 4 種 noise）| **0.31**（最高的那一格）|
| 梯度域的整張圖帶通 | **0.49**（局部最好）|
| 十七個古典對焦指標 | ≤ 0.51（Brenner 最高）|
| 不切塊的整張圖帶通 | 0.29（跟基準線分不出來）|
| 繞著 array 主頻的環狀 pattern 諧波能量 | 0.16 |

**沒有一組參數把它拉起來過。** 而且有一個很乾淨的線索說明為什麼：

> **把留下來的塊數從 19 掃到 40，兩台機台的 r 都一動都不動。**

那句話的意思是「前 30% 那一刀」與「梯度預篩」在 array 區**兩個都是 no-op** ——
它們的設計前提是「有些塊有 pattern、有些塊是空背景」，而 array 區每一塊長得
一模一樣。**那不是 bug，是前提不成立**：分數照樣算得出來，只是它的鑑別力有限。

（順帶：規格投影片寫「前 30」、詳細版寫「前 30%」—— 既然塊數掃動分數不動，
**兩種讀法在實務上沒有差別**。這個歧義結掉了。）

### 還沒問到的那一句話

**機台 A 的 F.I. 是在哪一個影像階段算的？它的正規化會不會跟同一批的其他張
有關？** 這兩個問題只有機台方答得出來，而答案可能會把整條路換掉 ——
所以在問到之前，**不要再盲調參數**，也不要為機台 A 另外加一張量測卡。

## 6. 出事了照這個順序查

1. **每一張分數都差不多** → 先看 §3：降位法選錯的樣子就是對比全部擠成一條
   窄帶。量一次 p1/p99。
2. **分數跟機台的 F.I. 對不起來** → 先確認 §4.3：這一組 `a`/`b` 是**這台機台
   這個區域**校出來的嗎？
3. **怎麼調都是 r ≈ 0.3–0.5** → 讀 §5。先問「這是 array 區嗎」，是的話試
   §2 的 `Its edges`；還是不行就是 §5 最後那一句話，回去問機台方，不要繼續調。
4. **空的角落看起來很清楚** → 那是 `iqi.py` 模組說明 ① 講的失效模式，
   把 `Also wash out noise above` 開起來。⚠ **logic 區不要開**：廠外實測
   `noise=20` 就讓 r 從 0.959 崩到 **0.06** —— 那一區的高頻是真的訊號。
5. **整張圖只有一小塊有 pattern** → 卡片上那一格 `Region`：拉一條區域線，
   只量你在意的那一塊（空白的角落本來就會把整張的銳利度拉低，而那不是失焦）。
