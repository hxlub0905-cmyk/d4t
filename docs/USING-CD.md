# 怎麼用 CD 這張卡

> **d4t — defect**　·　Measure 段的 `CD`（`cd_measure`）
> 這一份是**給使用者的操作手冊**：每一格是什麼、什麼時候該動它、動了之後
> 數字會往哪邊走。設計上的來龍去脈在
> [`docs/history/plans/F19-cd.md`](history/plans/F19-cd.md)，那一份不必讀。

---

## 0. 一分鐘上手

1. 在畫布上選一張上游的卡 → 從卡片庫加一張 **CD**。
2. **拉一條線**從影像流進 `source`（通常是 `test`）。這一格是唯讀的，
   來源只在畫布上決定。
3. 想只量某一塊 → 從 **Region 卡**拉一條虛線進 `Region`。不拉就是量整張圖。
4. 最上面那一格 **Measuring** 選 `一條線` 或 `一團東西`。
5. 看預覽影像：**量測線／輪廓有沒有壓在你想量的東西上**。
6. 有壓對 → 底下 Report 那一排勾你要的數字。沒壓對 → 往下看第 5 節。

**最重要的一句話**：這張卡的參數面板存在的目的，是**讓面板左邊那張圖看起來對**。
數字錯了從數字上看不出來，從圖上一眼就看得出來。

---

## 1. ⓪ `Measuring` — 一條線 / 一團東西

**這是一個真的岔路，不是一個選項。** 它問的是你的樣品，而且它決定了後面
哪幾格算數 —— 選錯的話下面的設定全部是在解一個錯的問題。

| 你要量的東西 | 選 | 為什麼 |
|---|---|---|
| 線、溝、trench、間距 —— **有方向的** | `一條線` | 沿著結構鋪一排量測線，每條量一次寬。N 條收成一個分布 → 除了寬度，**粗糙度是免費的副產品** |
| 顆粒、孔洞、殘留、刮傷、不規則缺陷 —— **沒有方向的** | `一團東西` | 硬挑一個方向去量一團東西，答案就取決於那個挑選。這一支給的是**旋轉不變**的描述（真實面積、等效圓直徑、旋轉卡尺）|

**判斷法**：把樣品在心裡轉 45°，如果「該量哪裡」的答案跟著轉了，那它有方向，
選 `一條線`；如果答案不變，選 `一團東西`。

一條 45° 的刮傷是後者 —— 它的 `cd_feret_max` 轉幾度都一樣，
而 bounding box 會給你一個大得離譜的數字。

⚠ **切過去之後，收起來的那幾列不是消失，是不適用。**「方向」對一團東西沒有
意義，所以那一列收起來 —— 不是攤在那裡讓你猜它算不算數。

## 2. ① 在哪量

### `source`（哪一條影像流）

**唯讀，只在畫布上拉線決定。**

| 通常接 | 什麼時候接別的 |
|---|---|
| `test` | 幾乎永遠是它。這張卡量的是**影像上的邊** |
| 正規化／去雜訊之後的流 | 原圖對比不穩、跨批亮度會漂的時候 |
| ⚠ **不要接 `diff`** | 差影像已經把結構減掉了，**邊也一起減掉了**。差影像上唯一還在的是缺陷本身 —— 那是 `一團東西` 那一支的場合，不是量線寬的 |

一次接**兩條流**（例如 `test` 與 `ref`）＝ 同一件事在兩條流上各做一次，
每個數字自動帶上流名前綴。要比「這一顆跟參考影像差多少」時很好用。

### `Region`（哪一塊）

**唯讀，從 Region 卡拉一條虛線過來。** 不拉線 = 量整張圖。

| 情況 | 做法 |
|---|---|
| patch 上只有一根線要量 | 拉一個框住它的區域 —— 框越貼，`auto` 那幾格越不會挑錯 |
| 想比較兩塊（例如缺陷處 vs 旁邊乾淨處）| **拉兩條線進來**。同一件事在兩塊各做一次，每個數字帶上區域名前綴（`epi_cd_median` / `mg_cd_median`），面板上一塊一列、一塊一個顏色 |
| 只想看整張 | 不拉 |

⚠ **拿掉上游那張 Region 卡，這張卡不會報錯** —— 它會安靜地改量整張圖。
所以畫面上那條虛線是你唯一的線索，它在就代表有在框。

Region 卡右邊的**三顆菱形埠**各是什麼（滑鼠停上去也會講同一句；GLV 卡同）：

| 埠 | 一句話（畫面上的原文）|
|---|---|
| `<名字>` | all the boxes —— 全部的框 |
| `<名字>_center` | the defect's box (a patch is guaranteed centred on it) —— 缺陷那格（patch 置中保證）|
| `<名字>_others` | the other boxes = the reference —— 其餘格 = 參照 |

## 3. ② 方向與極性

### `Direction`（`auto` / ↕ / ↔）　*只有 `一條線` 有*

| 選 | 什麼時候 |
|---|---|
| **自己指定**（↕ 或 ↔）| **整批長得一樣的時候，一律選這個。** 每一顆都用同一個方向量 = 這一欄 CSV 是同一種量測 |
| `auto` | 同一批裡結構的方向會變（例如轉角、不同 die 的 layout 不同）。它挑了什麼會寫進 `cd_axis_deg` |

⚠ **`auto` 的代價**：如果它在一批裡逐顆挑了不同的方向，`cd_median` 那一欄
就同時裝著兩種量測，而**每一顆都吐得出正常的數字**。
所以跑完一批一定要**畫 `cd_axis_deg` 的分布**：不是單一值的話，回來把方向釘死。

### `Measure the`（`auto` / 亮的 / 暗的）　*兩支都有*

問的是：你要量的是**亮的那個**（線、顆粒）還是**暗的那個**（溝、孔洞）。

同樣的建議：**知道就填死**。`auto` 挑的極性寫進 `cd_bright`（1 = 亮、0 = 暗），
而一批裡混了兩種的症狀跟上面一模一樣 —— 一欄裡兩群數字，肉眼看不出來。

> 這兩格是這張卡上最容易產生「跑得完、有數字、而且是錯的」的地方。
> 一批跑完，先畫 `cd_axis_deg` 與 `cd_bright` 的分布，再看 `cd_median`。

## 4. ③ 邊在哪 —— 數字真正的來源

**沒有一個「正確的邊」。CD 是被「你怎麼量」定義出來的。** 這一段的三格就是
那個定義，所以**同一份 recipe 要一路用到底**，不要中途換。

### `Edge is at`（判準）　*只有 `一條線` 有*

| 選 | 它是什麼 | 什麼時候用 |
|---|---|---|
| `threshold`（預設）| 亮度爬到兩側之間某個高度的地方 | **絕大多數時候。** 三個裡面**重複性最好**（σ 最小）—— 要看批內變異、看粗糙度、看趨勢，用它 |
| `gradient` | 亮度變化最快的地方 | **要比絕對值的時候。** 它幾乎不受模糊與平滑影響，所以跨機台、跨批比 CD 絕對數字時偏差最小 |
| `fit` | 沿整段爬升擬合一條 S 曲線 | 想順便知道**邊有多模糊**（focus 有沒有跑掉）時 |

⚠ **`gradient` / `fit` 只有線那一支有。** 它們是一維剖面上的構造，二維沒有
對應物 —— 所以 `一團東西` 只有門檻一種，而那一格會收起來。

### `…at this height`（%）　**兩支共用同一格**

高度**一律從暗算到亮**。50% 是慣例。

| 動它 | 亮的東西（線、顆粒）| 暗的東西（溝、孔洞）|
|---|---|---|
| 調高（→ 75%）| 量出來**變小** | 量出來**變大** |
| 調低（→ 25%）| 量出來**變大** | 量出來**變小** |

什麼時候會想動它：你的規格是用某個特定高度定義的（有些製程用 30% 或 80%），
或是邊的底部有 footing、想避開它。

> 這一格在兩支裡是**同一句話、同一支函式** —— 所以 `一條線` 與 `一團東西`
> 量出來的東西是在同一個定義下的。

### `Look this far around each edge`（px）　*只有 `一條線` 有*

決定「兩側的準位」拿多少像素來算。預設 9。

| 症狀 | 動法 |
|---|---|
| 結構很細、旁邊馬上又是另一根 | **調小**（太大會把隔壁的結構算進來）|
| 邊很糊、平台一直找不到 | **調大** |

卡片**永遠不會讓它跨過隔壁那條邊** —— 這一格是上限，不是實際用的量。

## 5. ④ 怎麼收 —— Report 膠囊

### `一條線` 的膠囊

**Width — 這條結構有多寬**

| 膠囊 | 是什麼 | 什麼時候勾 |
|---|---|---|
| `cd_median` ★預設 | 所有成功量測線的**中位數** | **這就是 CD。** 用中位數不用平均：一條量歪的線不該把答案帶走 |
| `cd_mean` | 平均 | 要跟舊系統的定義對齊時 |
| `cd_min` ★預設 | 最窄的那一段 | **頸縮。殺死良率的是最窄的那一段，不是平均** |
| `cd_max` ★預設 | 最寬的那一段 | 橋接 / bridging |
| `cd_range` | max − min | 想用一個數字概括「最糟到最好差多少」時。它是極值統計量，比 σ 敏感也比 σ 不穩 |

**Roughness — 它有多不齊**

| 膠囊 | 是什麼 | 什麼時候勾 |
|---|---|---|
| `cd_std` ★預設 | 各條線寬度的 σ ＝ **LWR** | 要看線寬粗糙度。⚠ **業界慣例的 3σ LWR = 這個值 × 3** —— 卡片一律報 σ，因為同一個名字在不同地方算出不同的東西是最糟的錯 |
| `ler_a_std` / `ler_b_std` | **兩條邊各自**位置的 σ ＝ LER | 想分辨「兩條邊一起晃」與「結構本身粗糙」。⚠ 這是兩種不同的製程故障：<br>· `ler_*` 大而 `cd_std` 小 → **兩條邊一起晃**（載台漂、對位漂）<br>· 兩個都大 → **結構本身粗糙** |

⚠ **要量粗糙度，`Average this many lines together` 一定要留在 1**（見第 6 節）。

**Vs target — 跟規格差多少**（要先填 `Target CD`）

| 膠囊 | 是什麼 |
|---|---|
| `cd_dev` | `cd_median − target`，px（正 = 偏胖）|
| `cd_dev_frac` | 同上除以 target，無因次 —— **要跨不同線寬的產品比較時用它** |

> `Target CD` 填 0 = 不算。填了之後這兩顆才有得勾，而**它通常才是值得拿去
> 分 bin 的那個數字** —— 「這一顆偏離規格多少」比「這一顆是幾奈米」更接近判定。

### `一團東西` 的膠囊

**Size — 有多大**

| 膠囊 | 是什麼 | 什麼時候勾 |
|---|---|---|
| `cd_area_px` ★預設 | **真實覆蓋的像素數**（不是外框、不是 w×h）| 「這顆有多大」最直接的答案。填了 nm/px 會多一份 `cd_area_nm2`（乘平方）|
| `cd_deq` ★預設 | 等效圓直徑 `2√(area/π)` | **要跟一個線寬門檻比大小的時候** —— 面積的單位是 px²，沒辦法直接跟 px 比 |
| `cd_feret_max` ★預設 | 旋轉卡尺的最大寬度（最長的那條弦）| 「最長有多長」。刮傷、鬚狀物 |
| `cd_feret_min` ★預設 | 旋轉卡尺的最小寬度 | 「最窄有多窄」。判斷會不會卡住一個間距 |

> Feret 兩個都是**旋轉不變**的 —— 樣品轉幾度，數字不變。
> 這正是它們取代 bounding box 的理由（實測一個 L 形的 bbox 是真實面積的 **1.9 倍**）。

**Outline — 長什麼樣**

| 膠囊 | 是什麼 | 什麼時候勾 |
|---|---|---|
| `cd_aspect` | `feret_max / feret_min` | **分「一條刮傷」與「一顆顆粒」**。圓 ≈ 1，細長 ≫ 1 |
| `cd_roundness` | `4π·area / perimeter²`（圓 = 1）| **分「一團實心的」與「一團毛毛的」**。⚠ 它跟 aspect 問的不是同一件事：一條直細棒與一團毛圓斑可以有一樣的 aspect，roundness 分得出來（前者周長短、後者長）|

## 6. 進階那幾格（`Show N more settings`）

平常不用動。動之前先確定你知道自己在換什麼。

| 格 | 支 | 預設 | 什麼時候動 |
|---|---|---|---|
| `One line every` | 線 | 1 px | 區域非常高、想跑快一點。**會減少量測線數，所以粗糙度變不準** |
| `Average this many lines together` | 線 | 1 px | 想讓每一條寬度不那麼吵。⚠ **要量粗糙度就別動它** —— 你要量的那個抖動，正好就是被平均掉的東西 |
| `Need at least this many lines` | 線 | 3 | 幾條線成功才算數。**兩條線的平均不是一個量測** —— 不足就整顆不寫寬度（計數還是會寫，所以看得出發生了什麼）|
| `Ignore blobs smaller than` | 團 | 4 px | 雜訊被切成一堆碎團的時候調大（看 `cd_pieces`）。這張卡看得見的最小極限大約 3×3 px |
| `Ignore edges weaker than` | **兩支** | 0.5 | 邊要比雜訊突出多少才算數（0 = 什麼都算，0.95 = 只認很乾淨的邊）。0.5 ≈ 對比至少是雜訊的四倍。**只有在「卡片漏掉了你肉眼看得見的邊」時才調低** |
| `Smooth each line by` | 線 | 1.0 px | 讓找邊撐得過雜訊。調很大會把 `threshold` 與 `fit` 的邊往外推（`gradient` 不會動）|

> ⚠ **`Ignore edges weaker than` 千萬不要調到 0。** 一條只有雜訊的線上，
> 「最陡的地方」永遠存在 —— 於是每一顆都量得出一個看起來完全正常的數字。
> 這是這張卡踩過最貴的一個坑。

## 7. 不用勾、一律會有的那幾個 —— 怎麼讀

**卡片自動做的每一個決定，都會變成一個你畫得出分布的數字。** 這幾個不在膠囊
裡，因為它們是**在讀 CD 之前先要看的東西**。

### 兩支都有

| 名字 | 是什麼 | 怎麼讀 |
|---|---|---|
| `cd_bright` | 1 = 量了亮的、0 = 暗的 | **整批應該是同一個值。** 兩群 = `Measure the` 的 `auto` 逐顆挑了不同極性，`cd_median` 那一欄混著兩種量測 |
| `cd_edge_score` | 這些邊有多可信，0–1（`對比/(對比+4×雜訊)`）| **量得準不準。** 整批畫出來就看得到門檻該往哪邊調。三個判準共用同一個公式，所以換判準之後還是可以互相比較 |

### `一條線` 才有

| 名字 | 是什麼 | 怎麼讀 |
|---|---|---|
| `cd_axis_deg` | 實際量的方向（0 或 90）| **整批應該是同一個值**（理由同 `cd_bright`）|
| `cd_lines` | 試了幾條 | 分母 |
| `cd_n` | 成功幾條 | 分子。`cd_n / cd_lines` 很低 = 掃描線沒壓對地方，先去看預覽圖 |

### `一團東西` 才有

| 名字 | 是什麼 | 怎麼讀 |
|---|---|---|
| `cd_pieces` | 門檻切出來有幾團 | **恆為 1 才代表沒問題。** >1 表示卡片自己挑了一團（中心那一團，沒有就取最大的）—— 通常是 `Ignore blobs smaller than` 太小，雜訊被切成碎團 |
| `cd_touches_edge` | 1 = 這團碰到區域的邊 | **那一顆的尺寸是下界，不是尺寸。** 卡片照量、但插了旗子並發警告。要完整的就把區域拉大 |
| `cd_feret_angle` | 最長方向（度）| 本身就有用 —— 一批刮傷的角度會聚在一起，一批顆粒的不會 |
| `cd_box_x` `cd_box_y` `cd_box_w` `cd_box_h` | **這一團在哪**（整張影像的像素，不是區域內的偏移）| 疊圖上那個紅框畫的就是它。⚠ **`w`/`h` 是框不是尺寸** —— 一個 L 形的框是它真實面積的 1.9 倍。要尺寸看 `cd_area_px` / `cd_feret_*` |
| `cd_cx` `cd_cy` | 這一團的**質心** | 「東西的中心在哪」。跟框的中心**不是同一個點**（L 形差很遠），而質心才落在東西上 |

## 8. 面板怎麼讀

**接了幾個區域就畫幾列，一列一個顏色 —— 而那個顏色就是影像上那個框的顏色。**

### `一條線`

| 格 | 畫什麼 | 用它回答 |
|---|---|---|
| 左（最大）| **一條線的剖面** ＋ 判準那條橫線 ＋ 兩個交點 ＋ 量到多寬 | **「為什麼是這個數字」。** 判準是什麼、邊被判在哪，一眼看完 |
| 中 | 每條線量到多寬（縱軸是沿著結構的位置）＋ ±1σ 的帶 | **「哪一段不齊」** —— 頸縮在這張圖上是一個往內凹的缺口，`cd_min` 那個數字答不出這件事 |
| 右 | 整批的分布 ＋ 這一顆在哪 | 「這一顆算不算離群」（跑過一批才有）|

### `一團東西`

| 格 | 畫什麼 | 用它回答 |
|---|---|---|
| 左 | 區域的**灰階直方圖** ＋ 判準那條線 | 剖面圖的同義詞：**門檻切在哪**。切太多／切太少不必先跑一批才發現 |
| 中 | 那一團的**輪廓**與最長的弦 | 「形狀長什麼樣」 |
| 右 | 整批的面積分布 | 同上 |

### 影像上

* **量測線／輪廓**畫在你量的地方，顏色 = 那個區域的顏色。
* **最粗的那一條**是代表值，也就是左邊剖面圖畫的那一條。
* **框還在、標記不見了** = 這一顆量不到。這是最有用的一個狀態，
  所以框（來自 recipe：你說要看哪裡）與標記（來自跑完的結果：真的量到什麼）
  **是兩個不同的來源** —— 混在一起就講不出這句話。

## 8.5 怎麼看「這一顆為什麼被判成這樣」

跑完一批之後，Results 的表格上**點那一列的 score / bin / class 任何一格**，
右邊會滑出一塊回溯面板 —— 它把這一顆的判定**重放一遍**：

* **Working numbers**：每一行 working number 的算式**帶著實值**
  （`bright = 42.5 (= 40 + 2.5)`）。有「missing ⇒ 用 __」的行，這一顆真的
  用了補值時會寫出來；跨整批換算（percentile / z）的行標著換算前的原始值。
* **The path it took**：判定樹一步一問，每一題帶實值與答案
  （`6.5 > 8 ? no`）。哪一題因為**沒量到**而答了「否」，那一行會直接點名
  是哪個數字沒量到。
* 最後一行是它落在的類別（跟表上那一格**同一份**，不是另外算的）。

面板上的每一項都可以**點**：點 `cd_median` 就跳到量它的那張 CD 卡；量在某個
區域上的數字（例 `epi_cd_median`）還會把**那一塊區域亮在影像上**（其他的框
變淡 —— 顏色仍然說「哪一塊」，亮度說「你問的那一塊」）。Esc 關面板。

> 面板上沒有任何數字是重算的 —— 值全部來自這一顆跑出來的那一列。
> 所以它跟 CSV、跟表格、跟 KLARF 寫回的**必然**一致。

## 9. 量不到的時候 —— 每一句話對應的動作

摘要那一行會直接講原因。**它比任何圖都有用。**

### `一條線`

| 它說 | 意思 | 做什麼 |
|---|---|---|
| `the structure ran past the edge of the region` | 結構被區域／畫面切掉了，找不到成對的兩條邊 | **把區域拉大**。卡片絕不把框的邊界當成一條邊 —— 那會發明一個等於區域寬度的假數字 |
| `no pair of edges around the middle of the region` | 找到邊，但中間那個位置沒有成對的一組 | 區域沒對準要量的結構；或 `Measure the` 選錯了極性 |
| `nothing with enough contrast to be an edge` | 這條線上沒有夠強的邊 | 換 `source`（是不是接到 `diff` 了）；或影像本身對比不足；真的看得見卻量不到才調低 `Ignore edges weaker than` |
| `the edge could not be pinned down` | `fit` 擬合失敗 | 換 `threshold` |

### `一團東西`

| 它說 | 意思 | 做什麼 |
|---|---|---|
| `nothing in it stands out from the noise enough to be a blob` | 這塊裡沒有任何東西比雜訊突出 | **這通常是正確答案**（假點就該量不到）。真的有東西才調 `Ignore edges weaker than` |
| `what stands out is smaller than the smallest blob this card counts` | 突出的東西比 `Ignore blobs smaller than` 還小 | 調小那一格（下限 ≈ 3×3 px）|
| `the region is too small to hold a blob` | 區域太小 | 拉大區域 |

> **量不到的那一格不會被寫成 0，也不會是 NaN —— 它不寫。**
> 0 進得了分數表達式、寫得進 KLARF，然後一路安靜到最後。
> 但「為什麼沒寫」留得下來：`cd_n` / `cd_lines` / `cd_edge_score` 照樣會有。

## 10. 三個完整的設定範例

**A. 量一根線的線寬與粗糙度（最常見）**

```
Measuring          一條線
source             test           ← 畫布上拉線
Region             （框住那根線的區域）
Direction          ↕（釘死，不要 auto）
Measure the        亮的（釘死）
Edge is at         threshold
…at this height    50 %
Report             cd_median · cd_std · cd_min · cd_max
Target CD          （你的規格值）→ 再勾 cd_dev_frac
```
跑完先看：`cd_axis_deg` 與 `cd_bright` 是不是各只有一個值。

**B. 判斷一顆缺陷有多大（真缺陷 vs 假點）**

```
Measuring          一團東西
source             diff           ← 這一支就是要用差影像
Region             （框住缺陷附近的區域，比缺陷大一圈就好）
Measure the        auto           ← 亮的殘留與暗的孔洞都可能
…at this height    50 %
Report             cd_area_px · cd_deq · cd_feret_max · cd_feret_min
```
跑完先看：`cd_pieces` 是不是恆為 1、`cd_touches_edge` 只有在大缺陷上是 1。

**C. 分辨刮傷與顆粒**

同 B，再加勾 `cd_aspect` 與 `cd_roundness`，並看 `cd_feret_angle`
——刮傷：aspect 大、角度聚集；顆粒：aspect ≈ 1、角度散開。

## 11. 幾件常常搞錯的事

| 以為 | 其實 |
|---|---|
| 「`source` 那一格可以打字」| **不行，它是唯讀的。** 來源只在畫布上拉線決定 —— 打得進去但畫布上沒有對應線條的話，畫面就在說謊 |
| 「`cd_std` 就是 LWR」| 是 σ。**業界慣例的 3σ LWR 要再乘 3** |
| 「`cd_area_px` 是外框面積」| 是**真實覆蓋的像素數**。外框對一個 L 形會大 1.9 倍 |
| 「量不到會給 0」| **不會寫那一格。** 0 是一個看起來很像答案的答案 |
| 「`auto` 比較安全」| `auto` 在**一批**裡可能逐顆挑不同答案，而每一顆看起來都正常。知道就填死 |
| 「單位可以在這張卡換成 nm」| 這張卡一律 px。**nm/px 填在 Load 卡上**，然後會**多**一份 nm 的（不是換掉）—— 名字帶著單位就永遠不必回頭查那份資料當初填了沒 |
| 「舊 recipe 的 `cd_x_px` / `area_px` 還在」| 已經拿掉了。舊的分數表達式引用它們會拿到 `unknown-feature` 警告，**那正是要看到的** —— 舊值是 bounding box，跟新值不是同一種量測 |
| 「位置也一起沒了」| 位置在（`cd_box_*` / `cd_cx` / `cd_cy`，2026-08-25 加回來的），只是**換了名字**。舊名不回來的理由就是上一列那一句：同一個名字換掉意思，比沒有那個名字糟 |
| 「`cd_box_w` 可以當寬度用」| **不行，那是框。** 一條 45° 的刮傷，框的寬度是它長度的 0.7 倍，跟線寬完全無關。所以這幾格**沒有** nm 版本 —— 有 nm 版的是真的尺寸那幾個 |
