# F28 — ADC 上畫布、Measure 段改名，Z-map 走人（2026-08-25）

使用者一次給了四件事：兩件動手、兩件問我的看法。這一份是動手的那兩件。

---

## 1. ADC 判定區：拖得動、拿得掉

> 「ADC 也要能在原畫布上拖曳 移除」

判定區以前是**全部唯讀**的（`tree_scene` 檔頭：「不可拖、不可刪 —— 樹是一個
結構，不是幾張散卡」）。那句話**仍然成立**，所以這一輪加的不是「每個菱形各自
拖」：

* **整區當一個東西拖**，把手是外框（`_ZoneItem`），不是裡面任何一張卡。
  一個一個拖的話畫面會長出樹上沒有的形狀（兩個菱形疊在一起、葉子跑到根的
  上面）—— 而畫布的職責正是「這棵樹長什麼樣」。
* **右上角一顆 ✕** ＝ 拿掉整個判定，而且**先問過**（底下掛著使用者自己畫的
  整棵樹，一顆 ✕ 的重量看起來卻跟刪一張卡一樣；`_remove_step` 對「yes 邊掛著
  一整個子樹」講過同一句話）。復原回得來。

### 兩個沒有動的東西

* **位置不進 recipe。** 跟卡片的位置一模一樣的待遇（session 狀態）——
  所以拖它不會讓檔案變髒、不佔一格復原，而 `Tidy up` 把它跟卡片一起排回去。
* **樹的形狀一個位元都沒變。** 動的只有畫布座標。

拖的時候**就地搬每一個圖元、不重建** —— 重建會把滑鼠從把手上搶走（F26 在拖
門檻時學到同一條）。累積的位移記在 `_tree_offset`，下一次真的重建時
`_rebuild_decision` 把它加回去。

⚠ ✕ **只有畫布接得住的時候才畫**（`_ZoneItem` 拿不到 canvas 就不畫）——
畫一顆按不動的鈕比沒有那顆鈕更糟。

## 2. Measure 段：GLV → CD → Focus index，Z-map 刪掉

> 「Measure 的 card 順序幫我改命名&重排：GLV → CD → Focus index
> （Z-map 功能請先幫我完整刪掉）」

### 改名：**只有 `label`**

| key | 以前 | 現在 |
|---|---|---|
| `glv_stats` | Gray level | **GLV** |
| `cd_measure` | CD | CD（不動）|
| `focus_quality` | Focus quality | **Focus index** |

`key` 是 recipe 的鍵、`glv_*` / `focus_*` 是分數表達式裡的變數名 —— 兩者都
不准動。那是 `CLAUDE.md` §5 那張表裡「只改 label」（零代價）跟「改名」
（要一道遷移）的差別。

**連帶抓到一個漂移**：`step.py` 有一句擋在使用者面前的錯誤訊息寫死了
「Use one **Gray level** card per pair」—— 改名之後它指著一張畫面上不存在的
卡。改成從 REGISTRY 問（`_label_of`），`tests/test_glv_compare.py` 當場抓到
它，而它抓得到正是因為它問的是 `label` 而不是那串字。

### 順序：住在 `steps/__init__.py` 的 import 序

`list_steps` 照 REGISTRY 的插入序回，而插入序就是 import 序。所以卡片庫裡
看到的先後**住在那三行**，不住在任何一張卡上。

### 刪 Z-map：代價量過了，而且很小

| 動到什麼 | 結果 |
|---|---|
| 卡片 `steps/snr_map.py` | 刪掉 |
| 兩份 fixture recipe 的三個 `snr_map` 節點 | 拿掉 |
| 三份黃金值 | 每一顆少一個 `snr_max` 欄；**分數與 bin 一個都沒有動** |
| `algo/snr.py` | **不刪**（見下） |

**為什麼這次很便宜**：沒有任何一張下游的卡讀 `snr_map` 那條流（`cd` / `glv`
讀的是 `test` 與 `diff`），兩份 recipe 的 score 也都不含 `snr_max`。
這跟 `pattern_ref` 那次完全不一樣 —— 那次 rsem route 的準確率從 24/24 掉到
12/24（`CLAUDE.md` §5 那張價差表）。

### ⚠ `algo/snr.py` 留著

它的呼叫者確實只剩測試，但 `snr_signed` 是**帶正負號那個慣例的規範出處** ——
GLV 卡的 `snr` 統計量照它做，而 `tests/test_steps.py` 就在斷言它還在。
同一條規矩 `algo/period.py` 與 `algo/golden.py` 已經寫過一次
（見 `d4t/ui/scope.py`）。**要刪它請先把那個慣例搬個家。**

## 3. 刪掉之後少了兩個「活例子」（值得記）

Z-map 是卡片庫裡唯一一張同時具備這兩個性質的卡，它走了之後**兩條規則還在、
但沒有卡片示範得出來**了。兩條都不是靠改測試蓋過去，是把話講清楚：

| 規則 | 以前的活例子 | 現在 |
|---|---|---|
| checkpoint 問的是「**會不會寫出影像流**」，不是 `category` 標籤（F17-③）| `snr_map` 是 `algo` 卻吐一條影像流 | 卡片庫裡**一張都沒有**了。`test_batch_cache` 的 checkpoint 數字從 7 變 6，而註解寫明「規則沒變，是例子沒了」 |
| 節點 id 可能**等於**一條流名（`viewmodel._new_id` 拿 step key 當 id）| `snr_map` 的 key 與流名都叫 `snr_map` | 也沒有了。`test_recipe_roundtrip` 那一條改成**斷言現在沒有** —— 哪天又出現一張，它會紅，而那正是它要講的話 |

同一族的第三個：**卡片庫裡現在沒有任何一張卡預設讀 `diff`**。`diff` 仍然
到處在用，但都是使用者接出來的。兩條「缺上游時要講出是誰產的」的測試因此
改用 `align_to`（預設吃 `paired`，只有 `pair_source` 產得出來）。
