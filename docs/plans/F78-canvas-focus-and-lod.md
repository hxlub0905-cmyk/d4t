# F78：畫布的「現在該看哪裡」＋ 主要按鈕的邊框（2026-09-02）

使用者：「我想要針對 Studio 的 UI 細節（畫布跟按鈕）做美觀，請給我建議。」

給了十條建議，這一輪做掉**代價最低的四條**（第 1、2、3、4）。剩下的六條記在
本文 §5，理由與代價都在那裡 —— 那幾條要動 token 與版面常數，而使用者定的順序
是「先把引擎做對，再回頭產品化」。

⚠ 這一輪**一行都沒有動 `studio.py`**（CLAUDE.md §4）。

---

## 1. 選中一張卡 → 它的線要跟著講話

**症狀**：點一張卡，畫面上只有那張卡自己有反應（accent 邊框 + 光暈）。
而使用者點它的理由通常正好是**「它接了誰」** —— 那個問題在畫布上要用眼睛沿著
線走才答得出來，而一張擠了十條線的 recipe 上根本走不完。

`_EdgeItem.paint` 以前只看**自己**的 `isSelected()`：一條線只有在使用者去點
那條線的時候才有反應。「選了一張卡」這件事，線完全不知道。

**做法**：`_EdgeItem.focus_state()` 回三種身分之一 ——

| 身分 | 什麼時候 | 怎麼畫 |
|---|---|---|
| `flat` | 沒有選中任何卡 | 原樣（`line_color(0.5)`、1.6px）|
| `near` | 接著選中的那張卡 | 同一個色相**調濃到 0.9**、2.2px |
| `far` | 有選，但跟它無關 | 往 `canvas_bg` 混 55% |

三件事刻意這樣定：

* **`near` 是「同一個顏色講大聲一點」，不是換成 accent 藍。** 線的顏色現在講
  的是「它從哪張卡出來」（F13-⑤ 的階段色混一半灰）—— 換成藍色會把那個意思整
  個蓋掉，而且使用者得多學一層「藍色 = 被選中的線」。
  `line_color` 因此多一個 `strength` 參數，那個「一半」變成呼叫端給的。
* **`far` 是退下去，不是消失。** 那些線仍然是這張圖的骨架，而使用者選完一張
  卡的下一個動作往往正是「那我上一張接的是什麼」。有一條測試守著它跟
  `canvas_bg` 的對比度 > 1.15。
* **接的是 `scene().selectionChanged`，不是補在 `set_selected` 裡。** 選取有
  三條路（點卡片、框選、程式呼叫），只補其中一條的話另外兩條選出來的卡片線不
  會亮 —— 而那是「有時候會亮有時候不會」這種找不到的 bug。

`has_node_selection()` 問的是**卡片**而不是 `scene().selectedItems()`：線自己
也是可選的，而「選了一條線」不該讓其他所有線都黯下去（有測試）。

## 2. 滑鼠移到線上 → 線本身也要動

`_hover` 以前只讓中點長出那顆紅 ×（F7-22）。但線可以橫過大半個畫布，× 離兩端
各一百多 px —— 餘光裡「我現在瞄到的是哪一條」沒有答案。

現在 hover 的線本身換成 `canvas_edge_active` + 2.4px。抬 z 值
（`hoverEnterEvent`）解的是「看不看得到」，這一條解的是「認不認得出」。

⚠ **hover 永遠贏過 `far`**：滑鼠壓著的那一條就是主角，即使它跟選中的卡無關。
不然會出現「滑過去了、× 也出現了，可是線還是灰的」。

## 3. 縮很小 → 卡片收掉小字（LOD）

背景的點陣底早就有這條線了（`drawBackground` 在 0.45 以下不畫點，理由是「會糊
成一片灰」），**卡片沒有**。於是 `fit()` 到 40% 的時候，每張卡上那兩行 6–7pt
的副標與設定摘要、加上左右各一排埠標籤，全部變成糊在卡片上的灰噪點 ——
而且每張卡還照跑一次 `_draw_elided` 的 elide 計算。

`_LOD_TERSE = 0.55` 以下：**標題留著**（那是這張卡的身分，也是唯一還讀得出輪
廓的一行，而且它會被擺到卡片中線上），副標、設定摘要、埠標籤收掉。
圖示磚、色條、警示標記、埠本身都留著 —— 縮小的時候要看的正是那些。

值取 0.55 而不是跟著背景的 0.45：**字比點更早糊**。`MIN_FIT_SCALE` 那裡量過
「副標要到 70% 才讀得回來」，0.55 是「已經讀不到了，別再畫」的位置。

## 4. 主要按鈕的邊框沒有跟著填色走

`#primary` 只在一般狀態寫了一次 `border: 1px solid $accent`，而 `:hover` /
`:pressed` **只換了 `background`**：

* hover：填色 `#3574d6 → #4a86e2`，邊框留在 `#3574d6` —— 一圈比自己的填色**深**
  的框，讀起來是「凹下去」，而 hover 該講的是「浮起來」。
* pressed：填色 `#2b5eb0`，邊框留在 `#3574d6` —— 一圈比填色**亮**的光暈。

兩個都是與該狀態相反的意思，而全平面設計沒有陰影可以蓋過去（`pressed_bg` 那
一輪 F7-23 第三輪講的是同一件事：底色得真的跳一階）。工具列與 `QPushButton`
兩份各兩條，共四條規則。

## 5. 沒做的六條（給下一輪）

| # | 是什麼 | 為什麼這輪不做 |
|---|---|---|
| 5 | **點陣底跟版面格線不是同一套**：`GRID = 22`，欄距 `NODE_W + COL_GAP = 320`（320/22 = 14.55）、列距 90（90/22 = 4.09）。按了「排整齊」之後卡片邊緣落在點與點之間，而且每列偏移量不同 —— 點陣底其實對不齊任何東西 | 要動 `GRID` 與 `_pitch`，而好幾條測試斷言座標。**這條的效益可能比配色大**：畫布「不夠俐落」的感覺很大一部分來自這裡 |
| 6 | **陰影與「全平面」自己打架**：`theme.py` 檔頭寫「沒有陰影」，`_NodeItem.paint` 畫的是一塊實心、單一 alpha、有硬邊的偏移方塊（那是重影不是陰影）。亮色 `canvas_bg #f0f1f4` 對 `bg_surface #ffffff` 只差 ΔL≈5，卡片其實靠 1px 邊框浮起來（暗色沒有這個問題）| 要先**選一邊**：拿掉陰影 + 壓深 `canvas_bg`，或改成三層遞減 alpha 近似模糊。這是使用者的決定不是我的 |
| 7 | **亮色的 hover 穿過工具列底色**：按鈕 `#ffffff`（亮於底）→ hover `#f0f2f5`（暗於底），中途穿過工具列的 `#f7f8fa`。暗色方向是對的（`#23262d → #282c34`）| `hover_warm` 被大量共用，要開新 token |
| 8 | **焦點環在滑鼠點完之後留著不走**（`QPushButton` 預設 `StrongFocus`；`QToolButton` 是 `NoFocus`，不受影響）。Qt 沒有 `:focus-visible`，但用一支記住 `TabFocusReason` 的事件過濾器 + 一個 `kbFocus` property 做得到 | 約 30 行、要開新模組 `ui/focus_visible.py`。可以獨立做 |
| 9 | **圓角沒有單一真相來源**：QSS 是 `radius_md: 6px`，節點卡是 hard-coded 的 `drawRoundedRect(body, 7, 7)` | 至少讓 canvas 讀 token（安全）；6 → 8 是口味，要先截圖比 |
| 10 | **全 repo 零動畫**。不建議大規模加，但 `fit()` / `reset_zoom()` / `tidy()` 的視角瞬間跳會讓使用者**失去「我剛剛在看的是哪一塊」** | 要一個 `ANIMATIONS` 開關給測試，不然 UI 測試會開始看時間 |

## 6. 為什麼這幾條驗得到

顏色／粗細的決定拉進 `_EdgeItem.line_pen()`、收不收小字拉進
`_NodeItem.terse_at()` —— **都不在 `paint` 裡**。

這是這個 repo 在 `shape()` / `cut_hit` 上學過的同一課（見 `_EdgeItem.shape` 的
說明）：**看得到的與測得到的必須是同一個定義**。寫在 `paint` 裡的話，要驗
「選中一張卡，它的線有沒有真的亮起來」只剩下數像素，而數像素的測試會在下一次
改字體或抗鋸齒時變紅，然後被關掉。

`tests/test_ui_canvas_focus.py`（11 條）＋ `test_ui_f7_23_buttons.py` 新增 2 條。
**每一條都做過反向驗證**（把改動拿掉，測試要變紅）：

* 拿掉 `selectionChanged` 的接線 → 5 條紅。
* 拿掉 `#primary:pressed` 的 `border-color` → 像素那條紅（兩個主題各一）。
* 把四條 `border-color` 全拿掉 → 結構那條紅，並且點名是哪四條規則。

⚠ 按鈕那條像素測試**第一版是假綠的**：它量的是 x=2，而那一格是填色不是邊框
—— 焦點環是畫在按鈕自己的填色上面的 2px 環（`focus_ring_inverse`，primary 上
是白的），把最外面兩格佔掉了。`_border_colour` 因此改量 x=0，並且**先斷言那顆
按鈕沒有焦點**。症狀是零：測試照樣綠，只是問錯了問題。

`:hover` 在離屏平台 render 不出來（`WA_UnderMouse` 與 `QHoverEvent` 都沒有讓
`QStyleSheetStyle` 進入 hover），所以 hover 那一半改用**結構**守：掃 QSS，
**只要一條 `#primary` 的狀態規則動了 `background`，它就必須同時講出邊框**。
那不是字串比對 —— 下一個人加 `:focus:hover` 或別的狀態時，這條會替他問一次。

黃金值三份全綠（`tools/freeze_golden.py --check`）—— 這一輪一個數字都沒動。
