## 1. 焦點環只在鍵盤導覽時出現（#8）

`QPushButton` 預設是 `Qt::StrongFocus` —— **滑鼠點一下它就拿到焦點**，而 QSS 的
`:focus` 對滑鼠點擊一樣生效。於是按完「Run trial」之後那顆按鈕留著一圈 2px 的
藍框，看起來像「還在啟用中」，要再點畫布上別的地方才甩得掉。

CSS 有 `:focus-visible` 表達「這個焦點是不是從鍵盤來的」，Qt 沒有。
`d4t/ui/focus_visible.py` 補的就是它：一支裝在 `QApplication` 上的事件過濾器，
把 `QFocusEvent.reason()` 寫成 widget 的 `kbFocus` 屬性，QSS 那邊改成
`[kbFocus="true"]:focus`。

四個決定：

* **文字輸入刻意不 gate。** 點進一個輸入框卻沒有任何邊框變化是**錯的**：游標
  在那裡閃，而「我現在打的字會進哪一格」需要那條框說出來。瀏覽器對文字輸入
  也是永遠 focus-visible。有測試守著兩邊（按鈕一條都不能漏、輸入框一條都不能
  被 gate）。
* **裝在 `apply_theme` 裡。** 樣式表與**餵給它屬性的那支東西**必須一起到 ——
  分開的話會有一種很難查的狀態：`[kbFocus="true"]:focus` 永遠沒有人把屬性設成
  true，於是焦點環從此不出現，而畫面上沒有任何錯誤。
* **切視窗不算滑鼠。** `ActiveWindowFocusReason` 時**維持原狀**，否則 Tab 到
  一半去看別的視窗、回來環就沒了。
* **一定要問「這是不是 widget」。** 裝在 QApplication 上的過濾器看得到送給
  **所有**物件的事件，而焦點事件也會經過非 widget 的物件（實測拿到
  `QCommonStyle`）—— 不擋的話 `widget.style()` 當場 AttributeError。

⚠ **`QToolButton` 的預設是 `TabFocus` 不是 `NoFocus`**（我第一版寫錯了）。
意思一樣（鍵盤到得了、滑鼠不給焦點），所以工具列沒有「按完留框」這個症狀 ——
但正因為鍵盤到得了，它的規則還是要一起 gate。

### 1.1 順手抓到一個真的 bug，以及一條空轉了很久的測試

`test_the_focus_ring_does_not_move_the_label` **從一開始就是空轉的**。

它比的是 `contentsRect()`，而 QSS 底下 `QPushButton.contentsRect()` 的邊界
**恆為 (0,0,0,0)** —— border 與 padding 一格都沒反映進去，所以那個比較永遠
相等、永遠綠。（第二版改成比「文字在按鈕裡的位置」也是空的：按鈕比 sizeHint
寬的時候 `QPushButton` 會把文字**置中**，padding 差 1px 完全不動它。）

真正看得見那 1px 的地方是 **`sizeHint()`** —— 環一出現按鈕就變大，而按鈕在
版面裡變大就是把別人推開。改成問它之後，當場抓到一個**真的 bug**：

> `#cardButton`（Card/Features 那顆切換）一被 Tab 到就**縮 2px**（90×30 → 88×28）。

原因：blanket 的 `QPushButton[kbFocus="true"]:focus` 為了它自己的 2px 環把
padding 還回 1px（`4px 11px`），而 `#cardButton` 的 base rule **刻意不宣告
padding**（幾何屬於 `[shape]`，見那裡的說明）—— 於是 blanket 的值就落到它身上。

⚠ 判準不是「每個 id 規則都要補 padding」：`#galleryChip` 也有 1px 焦點環，但它
的 base rule **有**宣告 padding，而 id 選擇器逐屬性贏過 `[kbFocus]:focus`，所以
它從來沒被影響（量過：兩種寫法都是 67×22）。**第一版我兩個都補了，`galleryChip`
那份是 no-op** —— 反向驗證那一輪它不變紅，才發現規則被我講錯了。

測試的 `KINDS` 同時補上 `#galleryChip` 與 `#cardButton` 的三種 `shape` ——
它們以前**完全沒有被問過**，而那四個正是最容易漏掉 padding 的地方。

## 2. 換視角要看得出「這兩張是同一份 pipeline」（#10）

`fit()` / `reset_zoom()` / `tidy()` 以前是**瞬間跳**的。瞬間跳會讓使用者
**失去「我剛剛在看的是哪一塊」** —— 前後兩張圖之間沒有任何線索說這兩張是同一份
pipeline。`tidy()` 更明顯：它同時搬動每一張卡，而按這顆鈕的人心裡還有一份舊的
位置圖，看得到每張卡從哪去到哪，那份圖才接得上。

`ANIMATE = True` / `ANIM_MS = 170`，`QVariantAnimation` + `OutCubic`。

**終點由原本那支函式自己決定，動畫一個字都不算。** 做法是先讓它跳到終點、把終點
量下來、再回到起點演 —— 所以不管 `fit` 的規則以後怎麼改（`MIN_FIT_SCALE`、
只縮不放、靠開頭對齊…），動畫都不會跟它分家。自己算一份終點的話，那份會漂。

同一個做法讓「被打斷」變成不用處理的事：任何時刻的**真相**都已經是終點，畫面只是
還沒追上。

兩個細節：

* 縮放用**幾何**內插（50% → 200% 的中點是 100%，不是 125%）。線性內插在放大時
  前段太慢、後段暴衝。
* `_set_view_state` 先設 transform 再設捲軸：捲軸的**範圍**是從 transform 算出來
  的，反過來會被舊範圍夾掉，而夾掉的那一下看起來就是「動畫結束時彈了一下」。
* 滾輪縮放刻意**不**走這條路：它本來就是一格一格的，加動畫只會變黏手。

⚠ **測試裡一律關掉**（`tests/conftest.py` 的 autouse fixture，跟「不准跳 modal」
同一種東西）。開著的話「按了 fit 之後縮放是多少」會變成一個跟時間有關的問題，
而那種測試會間歇性變紅、然後被關掉。`tests/test_ui_canvas_animation.py` 是全 repo
唯一開著動畫跑的檔案，自己開、驗完關回去，每一條都等動畫真的結束才斷言。

## 3. 圓角的家（#9）

`theme.radius(name) -> float`：QSS 寫的是 `"6px"`，自繪要的是 `6.0`。

以前自繪的 widget **沒有路可以讀 token**，於是各自寫死一個數字 —— 畫布上的節點卡
是 7、面板上的卡是 `radius_md` 的 6，兩個看起來是同一種東西的圓角差了 1px，而且
沒有任何東西擋得住它繼續漂。

⚠ **只收「卡片本體」那一族**（畫布節點卡 + 判定樹的入口卡，含它們的圖示磚與腳帶）。
repo 裡還有 20 幾個 2–4px 的圓角（進度條、小圓點、迷你 chip）—— 那些是**裝飾**，
跟卡片不是同一個物件。把它們也綁上來等於宣稱「改一次 `radius_md` 全 app 一起變」，
而那件事沒有人想要。

`radius_md` 6 → 8 那個**口味**問題沒有做，它跟 §5 是同一個決定的一部分。

## 5. #7 折進 #6：亮色的明度階不夠用

原本 #7 寫的是「亮色的 hover 穿過工具列底色」。量完之後那個描述不夠準，
而真正的問題比它大：

```
亮色： bg_surface 100.0 ／ bg_panel 98.6 ／ toolbar 97.6 ／ bg_page 96.5
       hover_warm 95.4（離 bg_page 只有 1.1）／ pressed_bg 88.3
暗色： bg_surface 15.1 ／ toolbar 12.7 ／ bg_page 9.8
       hover_warm 17.9（往**亮**走，離背景 8.1）／ pressed_bg 28.3
```

暗色的 hover 是**離開**背景（15.1 → 17.9，背景在 9.8 更下面）。
亮色的 hover 是**走向並穿過**背景（100 → 95.4，而 page 在 96.5）——
一顆 hover 中的按鈕跟它坐的面板幾乎同亮度，填色不再幫忙分辨圖與地。

而它修不掉，因為**亮色的四個表面全部擠在 3.5 個 L\* 裡**（100 / 98.6 / 97.6 /
96.5）。按鈕本身已經在 100，hover 只能往下；往下一點就撞到 page，往下夠多
（要到 91.5 才清得開 5）又變成「一按就變灰塊」，而且 `pressed_bg` 得跟著往下到
85 才維持得住 F7-23 那條「按下去要看得出來」的 ΔL ≥ 6。

**這跟 #6 是同一個根因**：`canvas_bg` 對 `bg_surface` 只差 ΔL 5，所以卡片其實是
靠 1px 邊框浮起來的，不是靠明度 —— 那也是那塊「陰影」當初被加上去的原因。

所以兩條一起，變成一個**要使用者選一邊**的決定：

| | 是什麼 | 代價 |
|---|---|---|
| **A** | 什麼都不動 | 亮色的層次繼續靠邊框撐；`theme.py` 檔頭「沒有陰影」那句話繼續是假的 |
| **B** | 真 flat：拿掉那塊陰影，`canvas_bg` 壓到 ~`#e6e9ee`（ΔL 9） | 跟寫下來的設計一致；亮色整體變「硬」一點；hover 那一階也一起解得掉 |
| **C** | 柔化：三層遞減 alpha（26/16/9，偏移 1/2/3）近似模糊 | 保留浮起感、仍是純 QPainter 不開離屏 buffer；但檔頭那句話要改掉 |

三張圖已經 render 出來（`opt-a/b/c.png`）。**這是設計決定不是工程決定**，
所以停在這裡等使用者選。
