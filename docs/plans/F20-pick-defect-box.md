# F20 — 哪一塊是缺陷那一塊

> 狀態：**引擎與 UI 都完成、實測驗過（2026-08-22）**。
> 相關：[`docs/USING-CD.md`](../USING-CD.md)、`_util.pick_defect_box`

---

## 1. 問題

三張找 ROI 的卡（Profile / Template / GDS layers）吐的是**一組**框，而下游要的是
其中一塊：`<name>_center`。在這之前「哪一塊」是寫死的一句話 ——

> 離 patch 正中心最近的那一塊。

那句話背後有一個假設：**patch 是以 KLARF 座標為中心裁的，所以缺陷就在正中心。**
假設成立的時候它完全夠用，而且不必接任何線。

但座標會偏。2026-08-22 在 `0822test/mgepi_real3`（48 顆合成 patch，缺陷位置
刻意灑開，離正中心中位數 7.1 px）上實測：

| 挑框規則 | 框到缺陷 | 框心到缺陷 | 下游凸出量 AUC | 正確率 |
|---|---|---|---|---|
| 離中心最近（原本） | **11 / 24** | 12.5 px | 0.688 | 72.9% |
| 訊號最強（這一版） | **24 / 24** | 2.5 px | **0.977** | **97.9%** |

**框放錯吃掉的比任何一個量測參數都多。** 同一份 recipe、同一支 `algo.edge`、
同一組 CD 參數，只換這一格。

> 要重跑這些數字：`python tools/make_mgepi_real.py <目錄>`（分離度那一批）與
> `python tools/make_mgext.py <目錄>`（校正那一批）。**資料不進版控**，
> 兩支都是固定種子、逐位元組可重現。

## 2. 做了什麼

一格參數，不是一張新卡。兩張卡（`roi_cross` / `roi_template`）共用同一份宣告：

```
Which box is the defect in     centre（預設，＝ 原本的行為）
                               strongest
Judge on                       ← 只有 strongest 時出現，type=image_key
```

| 位置 | 東西 |
|---|---|
| `_util.PICK_RULES` | 兩個規則的名字 |
| `_util.PICK_SMOOTH_PX` | 挑之前的均值視窗（3，寫死，見 §4） |
| `_util.pick_rule_specs(section)` | 兩張卡共用的那兩格 ParamSpec |
| `_util.pick_defect_box(boxes, shape, rule, signal)` | → `(索引, 真的用訊號挑了嗎)` |
| `roi_cross` | 兩格參數 ＋ `cross_pick_by_signal` |
| `roi_template` | 同上 ＋ `pick_by_signal` |
| `tests/test_pick_defect_box.py` | 11 條 |

**為什麼是一格參數而不是一張新卡**：兩者挑的是**同一組框裡的同一個東西**，
差別只在「憑什麼挑」。做成兩張卡的話，下游的 `<name>_center` 會有兩個來源 ——
而它們遲早會漂。

**為什麼兩張卡共用一份宣告**：同一件事在兩張卡上要一字不差，使用者只學一次。
`test_both_cards_say_it_the_same_way` 鎖住這件事。

## 3. 三條寫死的規矩

**一、判斷用的那條流是一條真的線。** `pick_source` 是 `image_key` + `direction="in"`，
而且 `resolve_reads` 在規則是 `strongest` 時把它宣告出來 —— 它會改變框挑到哪一塊，
也就是改變下游每一個數字，所以它必須進拓撲排序與快取簽章（鐵則 10）。
少了這一步，換一條線而簽章看不見就會回舊結果。

**二、接不到線就退回，而且要講出來。** 選了 `strongest` 卻沒拉線的話：退回
「離中心最近」、`ctx.warn` 說一句、而且 `*_pick_by_signal` 寫 0。
安靜地照做才是最糟的 —— 使用者以為挑的是訊號最強的那一塊，整批其實是用正中心挑的，
**而每一顆都吐得出正常的數字**。這正是 CLAUDE.md 那句「卡片自動做的每一個決定，
都要變成一個使用者畫得出分布的數字」。

**三、預設值不動。** `centre` 就是原本的行為。兩份黃金 recipe（`die_to_die_basic` /
`dual_route_basic`）24 顆逐欄比對：**沒有一欄變動、也沒有新增的欄**（那兩份沒有用
到這兩張卡）。用到 `roi_cross` 的既有 recipe 會多一欄 `cross_pick_by_signal`，
值是 0 —— 那是加法，不是改寫。

## 4. 為什麼「訊號最強」是「3×3 均值之後的最大值」

不是單像素的最大值：缺陷在 patch 上是 ~3 px 的一塊，單像素 max 在這種紋理上太脆 ——
一顆熱點就能把整塊框挑走（`test_a_single_hot_pixel_does_not_steal_the_box` 鎖住）。
3×3 均值是最小的匹配濾波，`snr_map` 用的是同一個理由。

視窗寫死不給調：它是「怎麼挑框」的一部分，不是「量什麼」的一部分，
而多一格能調的東西就多一種調錯的方式。要更強的濾波就把 `snr_map`（Z-map）
接進 `Judge on` —— 那本來就是它的用途。

## 4.5 UI 這一半（同一天，把 Studio 跑起來截圖才看到的）

引擎改完之後**實際跑一次 Studio 並截圖**，掉出四件「畫面在說謊」——
沒有一件是讀程式碼找到的。

| # | 症狀 | 病根 | 處置 |
|---|---|---|---|
| ① | CD 面板兩列都標 ``mg_center``、同一個顏色 | 列標題一律寫區域名，而「一列」也可以是同一個區域的**另一條流** | `inspectors.row_labels`：**只說出真正把它們分開的那件事** |
| ② | 疊圖上醒目的框 ≠ 卡片真的量的那一塊 | `_focus_box_index` 用「離畫面中心最近」算，而它的意思一直是 ``_center`` | 去問 context ``<name>_center`` 落在哪 |
| ③ | ref 的量測線畫在 test 的影像上 | `overlay_marks` 交出所有 note、`_refresh_measure_marks` 推給兩個 view | `overlay_marks(ctx, params, stream)` ＋ 一個 view 問一次 |
| ④ | GLV 面板寫 ``typical box #7 of 20``，影像上找不到第 7 格 | `glv_stats` 沒有 `overlay_marks` | 在典型那一格的**四個角各畫一個點** |

②是 F20 自己造成的回歸：改之前「離中心最近」與 ``_center`` **必定一致**
（那一版的 `_center` 就是這樣定義的），改之後不是了。

③在比對模式下特別明顯：左右兩張圖顯示不同的流，而兩邊畫的是同一組線。

④的第一版是「再描一圈外框」，**截圖出來才發現等於沒畫** ——
`ImageView._paint_marks` 的規矩是「線畫到幾乎看不見（alpha 70）、點畫滿」，
而那圈外框跟區域框完全重疊、同一個顏色。改成四個角點（畫面既有的語彙）。

順帶：量測卡選著的時候**不再亂指一個框**。一個 24 格的區域被 pooled 成一堆
像素時，沒有任何一格是特別的 —— 把離畫面中心最近的那一格畫成醒目，
等於在說一件不成立的事。要指哪一格走卡片自己的 `overlay_marks`。

測試在 `tests/test_ui_f20_panel_truth.py`（8 條）。

## 5. 還沒解決的（同一次實測掉出來的）

**`roi_cross` 放不出「中心落在兩種材質交界上」的框。**
`beside_vertical` 的框是從條紋邊界**往外**長的（`grid._edge_spans`：
`(b + gap, b + gap + w)`），所以框心一定落在隔壁那個材質裡，不會落在交界上。
而 CD「一條線」的錨點就是框心 —— 錨點沒踩在缺陷上就配不出邊。

實測：`vertical_width` 填真值 9.33 時 `cd_n` 幾乎全 0；把它**謊報成 4.33**
（＝ 把框往 MG 裡面推 2.5 px）之後框心正好落在 spacer 中心，才有上面那 97.9%。
`crossing` 那一支是同一件事的另一個面：框正好等於條紋本身，而 CD 需要條紋兩側各有平台。

`gap` 只能往外推、`inset` 只能往內縮，**沒有一格能把框往條紋裡面推**。
候選解法（都還沒做）：

1. `gap` 允許負值 —— 一個字的改動，但「離邊界多遠」變成可以是負的，語意會歪。
2. 新增一格 `Shift the box`（帶正負號，單位 px）—— 語意乾淨，但多一格。
3. `beside_*` 多一個「以交界為中心」的放法 —— 最貼近使用者要的那件事
   （「我要量那條交界」），但 `_spans_for` 那張表要多一列。

三個都還沒選。**選之前先確認這是不是一個真的需求還是這一批資料的特例。**
