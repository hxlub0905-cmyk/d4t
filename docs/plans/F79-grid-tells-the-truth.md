# F79：點陣底要說實話（2026-09-03）

[F78](F78-canvas-focus-and-lod.md) §5 那張表上的第 5 條 —— 使用者：「接著做」。

## 1. 症狀：一套不存在的對齊

畫布上唯一那個說「這裡有一套對齊」的東西，指的是一套不存在的對齊。

| | 值 | 對 `GRID = 22` |
|---|---|---|
| 背景點陣間距 `GRID` | 22 | — |
| 欄距 `NODE_W + COL_GAP` | 204 + 116 = **320** | 320 / 22 = **14.55** |
| 列距 `卡片高 + ROW_GAP` | 79 + 26 = **105**（出貨那份 recipe）| 105 / 22 = **4.77** |

兩組都不整除，所以按了「排整齊」之後卡片的左上角落在點與點之間，**而且每一欄
／每一列偏移的量還不一樣**：

```
欄 k 的左緣離最近的點： 0, 12,  2, 14,  4 px   ← (320k) mod 22
列 k 的上緣離最近的點： 0, 17, 12,  7,  2 px   ← (105k) mod 22
```

沒有人看得出「差 12px」，但**每一列差的量不同**這件事，眼睛在餘光裡是讀得出
來的 —— 讀出來的結論是「這張圖沒有排好」。使用者說不出哪裡怪，只會說不夠俐落。

⚠ 這一條**不是配色問題**，而它以前一直被當成配色問題在改。

## 2. 做法

### 2.1 `GRID` 22 → 20，而且搬到模組層

20 是**唯一不必動卡片尺寸就成立的值**：`NODE_W + COL_GAP` = 320 正好是 16 × 20。

搬到模組層是重點的另一半。它以前是 `PipelineCanvas` 自己的一個私有常數，只有
`drawBackground` 讀得到 —— 於是「背景說的對齊」與「版面做的對齊」是**兩套**，
各自演化，而沒有任何東西會在它們分家時抱怨。現在排版、拖曳吸附、背景三者讀同
一個 `canvas.GRID`。

### 2.2 列距進位到格線上

卡片高度是變動的（有「整批跑一次」腳帶的卡比較高），所以列距不能寫死：

```python
self._pitch = on_grid(max(高度) + ROW_GAP)      # 105 → 120
```

`on_grid` **往上**進位，不往下：列距是「這一列最高的卡 + 間距」，往下取整會讓
最高的那張卡貼到下一列去。代價是縱向多 15px。

### 2.3 拖曳吸附，`setPos` 不吸

`_NodeItem.itemChange` 在 `ItemPositionChange` 時把位置吸到最近的點上 ——
**但只在 `_dragging` 為真的時候**（`mousePressEvent` 開、`mouseReleaseEvent` 關）。

兩個理由，第二個才是硬的：

1. 吸附是**手勢的一部分**（拖到附近就對齊），不是座標系的性質。
2. `setPos` 是別的程式碼**重現**一個位置的路：彈出視窗要跟主畫布擺在一樣的地
   方、重建畫布要把使用者拖好的佈局放回去。那條路一旦量化就**不再是
   identity** —— 存 333 讀回 340、再存 340……每重建一次漂一格。這跟鐵則 9
   （`to_json_dict → from_json_dict` 必須是 identity）是同一種 bug，只是這裡
   漂的是像素不是分數。

第 2 點不是推論出來的：把吸附加在**所有** `setPos` 上跑一次，
`test_ui_canvas.py::test_dragged_positions_survive_edits_and_popout` 當場變紅。

## 3. 沒做的：卡片右緣

`NODE_W` 是 204，不是 20 的倍數，所以**卡片的右緣仍然不在點上**。

量過了：要讓它也落在點上得把 `NODE_W` 收成 200，而那 4px 是 F13-⑤ 花錢買回來
的標題寬度（190 → 204 的理由是 `Compare two streams` 被切）。

判準：**左上角對齊才是「這一排卡有沒有排好」的判準**，而右緣多出來的 4px 是同
一個常數 —— 每張卡都一樣，卡片之間不會因此歪掉。所以不付那 4px。
（`COL_GAP` 也可以 116 → 120 配 `NODE_W` 200 把欄距留在 320，那是同一筆交易的
另一種寫法，代價一樣。）

## 4. 測試

`tests/test_ui_canvas_grid.py`（7 條）。四個突變全部驗過：

| 把什麼拿掉 | 誰變紅 |
|---|---|
| `GRID` 退回 22 | 「欄距是格線的整數倍」那條 —— 而且它指名說欄距 320 不是 22 的倍數 |
| 列距不進位 | 3 條（列距、自動排版、排整齊）|
| 拖曳不吸附 | 「拖完停在哪」那條 |
| `setPos` 也吸附 | 「setPos 要逐位保留」＋ `test_ui_canvas.py` 既有的那條 |

第一條是**給下一個要改 `NODE_W` / `COL_GAP` / `ROW_GAP` 的人的絆線**：欄距一旦
不再是 `GRID` 的倍數，畫布上不會有任何錯誤，只會慢慢變得不整齊 —— 那正是這一輪
在修的東西，而它上一次是怎麼發生的沒有人知道。

黃金值三份全綠 —— 這一輪一個數字都沒動。
