# F68 — GLV：抓 defect 的主力卡

2026-09-01。使用者：「我希望 GLV 這張卡**遠比現在的功能強大更多**……因為
**抓 defect 就是靠 GLV 吃飯的**」＋「UI 會讓人看不懂，不管是上方畫布設定跟
下方的卡片詳細設定（**尤其是下方**）」。

計畫在動工前逐題問過一輪（見下面「砍掉的比加上的多」），所以這一份記的是
**做了什麼、以及為什麼有些事沒做**。

## 一、能力

| # | 做了什麼 | 之前為什麼做不到 |
|---|---|---|
| D1 | **方向**：`both` / `darker` / `brighter` | `odd_box_scores` 是 `\|v−baseline\|/spread`——最亮的格跟最黑的格平起平坐，「找最黑」找出來的可能是最亮的，**每一顆都是**，而畫面上看不出來 |
| D2 | 贏家那一格的**全套統計量** `<量>_worst` | `glv_worst_value` 只給 judge 那一個；`<量>_outlier` 是**另一個問題的答案**（那個量自己最極端的格，不一定同一格）。使用者要的「最黑那格的 Q25」因此只能靠把 judge 改成 q25 |
| D4 | `glv_boxes_over_k` / `_frac` | 只吐第一名 →「一顆髒點」與「整片漂移」在特徵表上長得一樣，而處置完全相反 |
| D7 | judge 可以是**跟參照比出來的量** | judge 只吃絕對統計量，而每一格的 `cmp_*` 在同一趟迴圈裡**早就算好了** |
| — | **逐格配對** `ref_pairing` | 見下面第二節——D7 少了它是個空包彈 |

**每一個新參數的預設值都是現行行為**，所以黃金值三份逐項相同（每個 commit 驗過）。

## 二、D7 是空包彈，而實測把它揪出來

寫完 D7 的第一版之後，測試造的資料上「照 delta 挑」與「照絕對灰階挑」
挑到同一格。量了一輪：

```
照 glv_median 挑 → 第 5 格
照 delta / abs_delta / ratio / contrast / overlap 挑 → 也是第 5 格
照 spread_ratio 挑 → 第 1 格（唯一不一樣的）
```

**病根**：參照是**一整塊、每一格共用**的，所以 `delta` = 這一格的統計量 −
**一個常數**，而 `odd_box_scores` 是 leave-one-out 的偏離量除以偏離量的散布
——**對整排減同一個數完全免疫**。

修法是使用者定調的那一句：**test 的第 i 格對上 ref 影像的第 i 格**。
ROI 那組矩形本來就同時套在兩張圖上，所以這個對應是天然的，只是以前被混掉了。
圖案（線、洞）因此互相抵消，剩下的才是真的不一樣的地方。

* 只在「參照是同一塊、只是在另一張圖上」時定義得出來——接的是另一塊區域的話，
  兩邊框數不同，第 i 格對不到第 i 格。
* **預設 per box**（那才是對的），而**舊檔案的數字一個都不准變**：
  `RECIPE_VERSION` 2→3 ＋ `_migrate_glv_ref_pairing` 把舊節點釘回 `pooled`。
* 「這個限制」本身寫成一支測試（`test_a_shared_reference_makes_most_comparisons_pick_the_same_box`），
  不是寫成註解——哪天它變了會有人知道。

「跟誰比」排在「怎麼找」之前，因為 D7 讓判準取決於有沒有接參照。

### 接線插槽（新模組 `d4t/ui/wiring_slot.py`）

那四格以前是**唯讀的 `QLineEdit`，而且沒有任何專屬樣式**——套的是通用輸入框
的長相，點下去還會亮 focus 框，**看起來就是可以打字**。現在是：

* 左邊一個符號，**跟畫布上那顆埠同形狀同色**（圓／菱形，參照那顆虛線邊）。
* 中間講現在接的是什麼，**沒接線不是空白**：`the whole image` ／
  `no reference — absolute numbers only` ／紅字 `not connected`。
* 右邊一顆按鈕，列出**上游真的產得出來的**，選了就建那條線——而它走的是
  **跟畫布拉線完全同一條路**（`_connect_region` / `_connect`），
  所以 undo、`rename_fallout`、健檢全部原樣繼承。

> 線仍然是**唯一的儲存**。這只反轉 F12 §2「改要回畫布上拉線」那半句，
> 而它有先例：F10-7 就是因為同一條規則擋住真實需求而被縮小過一次。
> 「兩條路存出來的 recipe 逐位元組相同」是一支測試。

### 畫布

* **角色決定外觀**：`ParamSpec.role`（`measure` / `reference`，宣告不推導）；
  參照那顆埠畫**虛線邊**（跟區域線同一個語彙）。以前兩顆菱形是逐位元組相同的。
* **標籤永遠說得出角色**：`ref cells_others`。以前接上線之後角色的字就消失
  ——分辨兩顆埠的唯一線索，在最需要它的時候不見了。
* **拖線時接得上的埠會亮起來**（以前完全沒有回饋）。
* **埠距 13 → 17px**：以前四顆埠相距 12.8px，而埠本身畫出來就 11px 寬。
  ⚠ 要守的不是「抓取圈不重疊」（就近吸附之下重疊無害），是**瞄得準**
  （`_PORT_MIN_GAP`）。

### 設定欄的選項也是膠囊（第二輪，2026-09-01）

> 「我希望設定欄這邊也是能像下方一樣膠囊 icon 配文字，這樣 user 比較會有感覺。」

上面那一段把四個假輸入框換成插槽之後，這張卡的設定欄還剩三個**純下拉**
（`Boxes in the region` / `Looking for boxes that are` / `Take the reference`），
而它們正好夾在膠囊與膠囊之間 —— 同一張卡上兩種長相，使用者要學兩次
（那正是 F18 把統計量從勾選框換成膠囊的原話）。

新的參數型別 **`chip_choice`**：一排膠囊，選一顆，**圖與字都留著**。

* 外觀**只有一份**：`_MetricChip` 抽出 `_ChipBase`（尺寸、字級、選中的畫法、
  hover），統計量那一族與設定欄那一族各自只實作「小圖怎麼畫」。抄第二份出來
  的那份會漂走，而漂走的症狀是同一張卡上兩種高度的膠囊。
* 值的格式跟 `choice` **一字不差**（就是那個字）—— recipe JSON 沒有變，
  黃金值三份逐項相同。
* 七張新的小圖（`boxes_*` / `odd_*` / `pair_*`）畫的是**那一格在問的事**：
  格子併成一堆還是一格一格、偏出去的那一根往下（暗）還是往上（亮）、
  參照是一格對一格還是全部對一個數。

**跟 `icon_choice` 的判準**（寫進 `ParamSpec.icons` 的說明）：意思在圖裡還是
在字裡。`beside_vertical` 那個詞講的就是一個形狀，圖給完了字是多的
（`icon_choice`，名字退到 tooltip）；`each box` / `per box` 是**做法**，
圖只能當掃視時的錨點，拿掉字就沒有人看得懂（`chip_choice`）。
所以 CD 那三格（一條線／一團東西、方向、亮的還是暗的）**一格都不動**。

### 整張卡片庫（第三輪，2026-09-01）

> 「同時請整理所有卡片，我認為設定區都要變成這樣 icon 膠囊 + 文字，
> 並且**視覺模型可能要接近**會比較好。」

GLV 那三格證明了做法可行，這一輪把它套到**每一張卡**：25 格選項
（18 個純下拉 ＋ 7 個 `icon_choice`）全部變成 `chip_choice`，
新畫 **61 張小圖**，住在新模組 `d4t/ui/glyphs.py`
（`CLAUDE.md` §4 早就指名「那幾群自繪圖示最好拆」）。

**「視覺模型要接近」＝ 一套文法，寫在那份的檔頭**：

1. 淡的是**原本就在那裡的東西**（影像、圖案、所有的框），
   實心的才是**這個選項在講的那件事**（F11 Region-2 傳下來的）。
2. 同一排的差別做在**位置與形狀**，不做在粗細（19 px 下分不出來）。
3. 一排裡的每一顆**共用同一個底** —— Normalize 五顆都畫在同一張直方圖上、
   Image Combination 五顆都是「兩張圖 ＋ 中間那個運算」、CD 三顆都畫在同一條
   邊的亮度剖面上。
4. **只有畫得出來的才畫。** 畫不出來的時候圖是裝飾，而裝飾會讓使用者以為
   那裡有意思可以讀。

**`icon_choice` 刪掉了**（只有圖、名字退到 tooltip）。它的理由仍然成立
（`beside_vertical` 那個詞講的就是一個形狀），但使用者看了整個設定區之後的
判斷相反：同一個面板上兩種長相，使用者要學兩次。`choice`（純下拉）留著當
「這一排真的畫不出圖」的退路，而 `test_no_card_anywhere_still_shows_a_bare_dropdown`
會擋 —— 那正是停下來想一下的地方。

兩件順手修掉的（都是 render 出來才看到的）：

* **`_spell` 用了 `str.capitalize()`**，它會把其餘的字**全部轉小寫** ——
  於是 `a cell I mark myself` 在畫面上是「a cell **i** mark myself」，
  使用者自己寫的一句話被一支拼字函式改掉了。
* **長的列名會把膠囊擠扁**：「Take the up-and-down stripes that are」把名字那
  一欄撐到三百多 px，七顆膠囊排成五排參差不齊的東西。名字是一欄（換行、
  上限 152 px），膠囊是一塊。

拼不對的值走 `ParamSpec.choice_labels`（`zscore` → `Z-score`、`nlm` → `NLM`、
`topn` → `Top N`）—— 理由跟 `label` 一字不差（「參數名是 recipe 的鍵，不是給人
看的字」F7-9），只是換到**值**上。那張表**只放例外**，打錯一個值會在註冊當下
擋下來（不然它只是安靜地不生效，而畫面看起來完全正常）。

⚠ 一條既有的測試因此紅了，而它是對的：`test_card_invariants` 的
「改一個參數，快取一定要跟著失效」只認得 `type == "choice"` ——
`icon_choice` 從來沒有被它蓋到，而全部換成 `chip_choice` 之後漏掉的從 7 個變成
21 個（56 < 60 的下限）。現在三種都算，覆蓋率比這一輪之前**還高**。

### 最上面那一排 preset 也是（第四輪，2026-09-01）

> 「最上方的 What do I want to measure 也是，而且我覺得他**有一點太口語**？」

**長相**：那三顆 `QPushButton` 變成同一種膠囊。它問的是同一種問題（幾個答案
挑一個），長成另一種東西只會讓人以為那是別的機制 —— 而它其實正是底下那幾格
的**捷徑**，所以三顆的圖就是它們會設成的那幾格的圖（`boxes_each` /
`boxes_pooled` 直接取自 `across_boxes` 那一排；兩張表由一支測試對起來）。

**用字**：帶冠詞的口語短句跟底下每一格的膠囊不是同一種語氣，而它們排在上下
兩公分內。

| 以前 | 現在 |
|---|---|
| What do I want to measure? | **What to measure** |
| The defect's box | **Defect box** |
| The most unusual box | **Odd box out**（這張卡自己的詞：`Pick the odd one by`）|
| The whole region | **Whole region** |

膠囊多兩個狀態：**灰掉**（roi 那條線還沒接 —— 選中的那一顆照樣看得出是選中
的，它是現在的狀態不是一個待選項）與 **momentary**（preset 不是開關：再按一次
要回到哪個狀態沒有答案，所以按了只發訊號，勾不勾由下一次重畫決定）。

⚠ **換過來的時候掉出一個以前就在的 bug**：`set_intent_row` 重建時只做
`removeWidget` + `deleteLater()`，而延遲刪除要等事件圈的 DeferredDelete 那
一趟 —— 在那之前舊的那幾顆**還在畫面上**，停在上一次版面給它們的位置。
以前是按鈕、每次寬度都一樣所以完美重疊，看不出來；膠囊那一排有彈簧，面板
一換寬度位置就變，於是舊的疊在標題與新膠囊上。修法是先 `setParent(None)`。

## 四、砍掉的比加上的多（每一條都有使用者的一句話）

| 沒做 | 依據 |
|---|---|
| 逐像素／滑動視窗（我提過、量過、畫過圖） | 「**框跟缺陷差不多大**」——逐框就是對的尺度 |
| 位置對位置的**像素**比對 | 同上；GDS 的材質區也沒有等大的框可以對 |
| 框跨界的處理 | 「**不太會**」 |
| 局部基準（只跟附近的格比） | 「**全部其他格（現狀）**」 |
| 框往內縮 n px（我提過） | 框≈缺陷 → 內縮會**切到缺陷本身** |
| Cell to cell／Die to die 當標籤 | 「**概念上不太對**」——那是機台檢測當下做的事 |
| 把 align 卡拿回來 | 「**跟這裡無關也不需要對齊**」 |
| KLARF 寫分數 | **已經做得到**（`output_klarf.include_annotations`）|
| 連通塊／blob | `find_defect` 是使用者叫我刪的，不從後門長回來 |
