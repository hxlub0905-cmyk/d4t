# F82：拖曳改成磁吸（2026-09-03）

使用者回報：

> 「目前在畫布拖動沒有像之前那樣絲滑的感覺（有點是一格一格的），這是我們哪部
> 改動造成的?」

是 [F79](F79-grid-tells-the-truth.md) 的拖曳吸附。而那個描述是**準確的**。

## 1. 我把取捨搞錯了，而且沒有講出來

F79 的 `_snapped` 是**無條件**量化：每一次滑鼠移動都被 `round` 到 `GRID`（20）
的倍數。所以：

* 100% 縮放時，一步 20 螢幕 px
* `fit` 到 54% 時，一步約 11 螢幕 px

也就是**卡片從頭到尾沒有一刻跟著游標走** —— 它一直在一個晶格上跳。對齊買回來
了，跟手賠掉了，而我在 F79 的計畫書裡把它寫成「拖到哪都會吸到最近的點上 ——
那是點陣底存在的理由」，完全沒有提到代價那一面。

## 2. 磁吸

大部分的行程 1:1 跟著游標（那就是「絲滑」），只有離格點很近的最後幾 px 才被吸
過去。兩件事都保得住。

三個決定：

* **半徑用螢幕座標**（`SNAP_REACH_PX = 4.0`），除以縮放換算回畫布座標。
  手感要跟縮放無關：不換算的話，放大到 200% 時磁區在螢幕上是兩倍寬（黏），
  縮到 50% 只剩一半（形同沒有）。
* **上限一定要夾**（四分之一格）。縮到 40% 時 4 / 0.4 = 10 畫布 px，正好半個格
  —— 磁區把整條軸蓋滿，於是**退回無條件吸附**，也就是使用者不要的那個。
  夾住之後任何縮放下都留得下一半以上的自由行程。
* **逐軸判斷**。x 對齊了而 y 還在中間是合法的狀態；用歐氏距離會把兩軸綁在一起，
  於是「我只想對齊左邊」做不到。

`setPos` 仍然**完全不吸**（F79 §2.3 的理由沒有變：那是別的程式碼重現位置的路，
量化它就不再是 identity）。

## 3. 測試連錯兩次，兩次都是同一種錯

`test_a_card_you_drag_lands_on_a_dot` 換成三條（近了會吸／中間不吸／逐軸），
而寫的過程中 `_drag` helper 被抓出兩個 bug —— **兩個在無條件吸附時都看不出來**，
因為結果都被 `round` 掉了：

1. **每一顆事件都從場景座標重算 view 座標。** 拖曳途中 sceneRect 會長大
   （`test_a_card_dragged_past_the_edge_stays_reachable` 守的就是那件事），
   捲軸跟著位移，於是同一個場景點對應到另一個 view 點。
2. **一步跳過去，而不是連續移動。** 真實滑鼠每一顆 move 都相對於當下的捲軸
   位置，所以捲動造成的偏移會被下一顆自己修回來；一步跳的話那個偏移沒有機會
   收斂 —— 實測一次 (30, 50) 的拖曳停在 (44, 50)。

現在是 12 顆 move，照著真實滑鼠的樣子走。

## 4. 突變驗證：**真正決定行為的是上限，不是半徑**

| 突變 | 結果 |
|---|---|
| `SNAP_REACH_PX` 4 → 100 | **沒有變紅** |
| 拿掉上限 | 「每個縮放都留得下一半自由行程」變紅 |
| `SNAP_REACH_PX` → 0 | 兩條「會吸」的變紅 |
| 改用歐氏距離 | 「逐軸」那條變紅 |
| 上限 0.25 格 → 0.5 格 | 「每個縮放…」變紅 |

第一列是這一輪最有用的一條資訊：**半徑調大是無效的**，因為上限把它夾住了。
所以下一個想「讓磁吸強一點」的人要動的是上限，而那正好是有測試守著的那一個
—— 這是對的排列（想放寬吸附就必須先面對「還剩多少自由行程」這個問題），
但它不是我設計出來的，是突變測試指出來的。

黃金值三份全綠 —— 這一輪一個數字都沒動。
