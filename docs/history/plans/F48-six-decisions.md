## 1. `GROUP_ALGO` 刪掉

詳見 [`F41-phase3-delete-algo-cards.md`](F41-phase3-delete-algo-cards.md) §5.1
（決定住在提問的那一份，不抄第二份）。這裡只記兩件在別處讀不到的：

* **它比想像中便宜**：`_GROUPS = GROUP_ORDER` 那一行看起來像個驗證表，實際上
  **沒有任何地方用它** —— 所以刪一個常數不會讓宣告它的卡註冊失敗，只會讓那張
  卡列不出來。代價因此只有一句話（寫在常數原本的位置上）。
* **兩條測試翻面、一支死圖示刪掉**。`GroupIcon` 的 `elif g == "algo"`（Σ）在
  F24 §5 之後就走不到了 —— 那個檔案裡的圖示是一段一顆，而「有圖示、沒有那一
  段」正好是下一個人照著加卡的形狀。

## 2. `adc` 段：**前提是錯的**，所以決定退回去

使用者答「拿掉」，根據的是 F41 §4.2 寫的「刪掉之後 `adc` 段零張卡」。實機查
證之後那句話不成立 —— 那一段裡有一張 `Score / Bin`（`studio._SCORE_LIBRARY_ENTRY`
釘進去的偽卡，點它 = `add_decision()`）。F41 §4.2 是**從 registry 數的**，
而使用者按的是畫面。全文與那條通則記在 F41 §5.2。

### 使用者的反問：「為何不能讓它就變成一張真的卡片?」

**做得到，而且它會消掉一份真的重複**（卡片庫現在是
`visible_steps(list_steps()) + [_SCORE_LIBRARY_ENTRY]` —— 那顆釘進去的偽卡站在
`test_card_library_order.py` 的不變量外面）。但代價不小，量出來是這樣：

| 動到 | 為什麼躲不掉 |
|---|---|
| **參數的型別** | 判定的內容是一棵**樹**（巢狀的 step／葉子／`let`／類別名），不是一組平的參數。`ParamSpec` 最接近的先例是 `type="curve"`，而曲線只是一串控制點；樹要一個新的 `type="tree"`，而它的編輯器就是現在的 `tree_panel.py` ＋ `tree_scene.py`（F24 開那兩個模組正是因為 `ParamForm` 編不動樹） |
| **recipe 的結構** | `decide` 現在是 JSON 的**頂層鍵**。搬進 `nodes` = 一道遷移，而且要證明 `to_json_dict → from_json_dict` 仍然是 identity（鐵則 9）、快取簽章跟著改、三份黃金值不變 |
| **引擎** | `_eval_score` / `_eval_decision` 跑在 DAG **之後**，不是 `execution_order` 裡的一個節點；`recipe.decide` 在 `d4t/` 底下被引用 **70 次、跨 11 支模組**（core 5、UI 6） |
| **畫布** | 判定現在是 `tree_scene` 畫的一組菱形（帶分支流量、判定引用），不是一張節點卡。變成「真的卡」之後要嘛保留那套特殊繪製（那它只是名字上的卡），要嘛失去樹的編輯介面 |
| **單一性** | 卡片可以加、可以刪、可以複製；判定**每條 pipeline 恰好一棵** |

**建議：現在不做。** 不是因為它不對 —— 而是它是一次動到引擎與 recipe 格式的
重構（F48 規模不只，該是自己的一輪），而使用者定的順序是「先把引擎做對，再
回頭產品化」（[`../ROADMAP.md`](../../ROADMAP.md)）。

**便宜的中間路**（如果目的只是「不要有第二份卡片來源」）：把
`_SCORE_LIBRARY_ENTRY` 拉進 `test_card_library_order.py` 的不變量裡 ——
它仍然是偽卡，但至少跟 registry 的那些受同一條測試管。

## 3. Results 有自己的入口了

**問題被換掉了，這一點值得記。** F26 草案 7／F27 §5 第一條問的是「Results 要
不要變成主視窗的第二個分頁」（一個會動到整個 Studio 版面的決定，三個版面案
擺了四天）。使用者要的其實是別的東西：**「目前是跑完才會出來」** ——
他要的不是它住在哪，是它叫不叫得出來。

* 工具列 `Results`（`popout` 圖示，跟畫布那顆「Open the pipeline in its own
  window」同一個字彙）＋ `Ctrl+Shift+R`；
* **還沒跑過也開得起來**，而空的時候視窗自己講在等什麼（F44 的 empty_reason
  同一條規矩）；
* 放在 Help／主題那一段，不放在 `Run trial` 右邊 —— 動線上「跑 → 看結果」
  確實是那個順序，但工具列的最後一格留給那顆藍鈕
  （`test_the_toolbar_is_grouped_not_one_long_row` 守著），而那一段的定義
  正好是「不屬於流程、但要隨時找得到」。

### 自己種的坑：**工具列早就滿了**

第一版把那顆鈕加在最右邊，全套測試跑起來紅的是一條**看起來不相干**的老測試
（`test_no_separator_fences_off_an_empty_stretch_of_toolbar` —— 分隔線後面
空無一物）。查下去才知道：工具列在預設視窗大小下**內容 916 px／視窗 948 px，
已經是滿的**，Qt 於是把放不下的最後一顆收進右邊那個 `»` 溢位選單，
`isVisible()` 是 `False`。

> **一顆藏在兩層選單底下的鈕，答不了「加一個按鈕」這個要求。**

修法不是把鈕做小，是**讓預設視窗大小由工具列的 `sizeHint` 決定** ——
以前那個 948 是 Qt 從版面湊出來的，沒有人選過它。新的不變量有自己的測試
（`test_the_results_button_is_actually_visible_at_the_default_size`）：
**下一顆鈕加上去而放不下的時候，紅的是那裡，不是一條講分隔線的老測試。**

## 4. `bin` 就地改 —— 只在畫面上

使用者：「只在畫面上，標成『手動改過』」。所以 F27 §5 那個「看結果 vs 編結果」
的張力**沒有被解開，是被繞開的**：改的那個值一個位元組都流不出這張表。

* 值住在 model 自己那份 row 副本的 `bin_override` 鍵上
  （`set_results` 收到的 dict 走 `dict(r)` 淺拷貝）；引擎判的那個仍然在 `bin`
  —— **兩個都要留得住，才講得出「從 5 改成 3」**；
* 格子裡寫的是 `3 (was 5)`（引擎沒判出來的那一顆寫 `7 (manual)`）。
  **兩個數字都寫出來**，不是一個記號配一句 tooltip —— 「引擎判 5、我說是 3」
  正是這一欄現在在講的整句話；
* 排序跟著手寫的值走（`sort` 與 `data` 都走 `_cell`，一個出處）；
* 一改就在狀態列講那句「這只在畫面上，CSV／KLARF 還是引擎的值」——
  **主動講**，因為使用者剛改完的那一刻心裡的問題正好是這個；
* **再跑一批就清掉**（`set_results` 重建 rows）。刻意的：那些記號講的是上一批
  的數字，留到下一批會變成一句沒有主詞的話。

### 手勢的衝突要先查清楚

這張表的單擊（判定欄 = 問「為什麼」，PR-3 的回溯面板）與雙擊（= 去看那一顆）
**都已經有人用了**，而 Qt 的 edit trigger 是**整張表**的設定 —— 加
`DoubleClicked` 或 `SelectedClicked` 的話同一個手勢會同時開回溯面板跟一個編輯
框。所以走 `EditKeyPressed`（F2／Enter，一個還沒有人用的手勢），發現得到那條
路走右鍵選單（順便支援「選一群一起改」——複審是一次看一群）。

### 驗收

`tests/test_ui_results_bin_override.py`（10 條）。最重要的那一組不是「改得動」，
是**改了之後那個值哪裡都去不了**：匯出的 CSV **逐位元組相同**、原本那份 result
dict **逐鍵不變**、再跑一批記號就沒了。兩個突變都驗過會紅
（拿掉 `dict(r)` 拷貝、`_cell` 不看 override）。

`test_ui_results_table.py` 那條「整張表唯讀」**翻面**成「除了 `bin` 以外唯讀」
—— 而那個例外的內容（去不了任何地方）只寫在上面那一支，不抄第二份。
