# F50 — 畫布上只剩卡片和線（2026-08-28）

**狀態：✅ 完成。** 使用者一次點頭六件事，全部做完。

起點是一個 bug 報告與一個直覺：**「output 這邊顯示蠻怪的，拖曳他的框會留下
殘影」**、**「output 用卡片合適嗎（原因是 input 有用卡片）」**。

而底下那句話是這一輪真正的授權依據：

> **「如果不一致，會有兩套準則，真正的使用者反而不知道怎麼用。」**
> **「使用者是不會寫 code 的人，但只要他看得懂每張 card 在幹嘛，
> 那他就能用拉線去達到他想要的事。」**

---

## 0. 先更正一個題目：Output 卡**已經是**節點了

`output_report` / `output_klarf` / `output_char` 都在 `recipe.nodes` 裡、都畫
在畫布上、都排在 `execution_order` 裡。使用者看到的「框框區」是 F30 畫在它們
**外面**的一個虛線框（`ui/output_band.py`）。

所以題目不是「把 Output 變成卡片」，是**把那個框拿掉**。

## 1. Output 去框：編碼錯了，不是資訊錯了

那個框要講的事是對的（**這幾張整批只跑一次**，其他每一張是一顆一次）。
錯的是編碼：

> **框的意思是「這幾個是一組」，而真相是「跑的時間不一樣」。**
> 那是一張卡**自己的屬性**，不是一群卡的**關係**。

改成卡片底下一條寫著 `once per lot` 的腳帶。三件事一次拿到：Output 卡長得跟
Input 卡一樣（使用者要的一致性）、殘影由構造上消失、畫布少一個概念。

**用字不只用顏色**（推廣鐵則）：一條色帶對不會寫 code 的使用者不是一句話。

**判準是 `Step.scale` 不是 `group`**：「Output 段」與「整批跑一次」今天剛好
是同一組卡，而那是巧合不是定義 —— `step.py` 的 `SCALE_LOT` 說明就寫著 Output
卡以前借用 `CATEGORY_ADC` 只是因為那個值剛好讓它們落在快取 checkpoint 之後。
腳帶講的是時間，判準也要是時間。

### 殘影的機制（值得記）

`canvas.refresh_edges()` 在**每一個拖曳 frame** 都呼叫 `_rebuild_output_band()`
—— 那個框是從卡片位置算出來的，所以卡片一動就得整個銷毀重建。而畫布沒有設
`setViewportUpdateMode`，用的是 Qt 預設的 `MinimalViewportUpdate`：抗鋸齒的
虛線圓角矩形每 frame 溢出 `boundingRect` 一點點，累積起來就是使用者看到的殘影。

> **會動的東西不要每 frame 重建。** 腳帶畫在卡片上，跟著卡片走 ——
> `refresh_edges` 因此不必為它做任何事，新測試守著那條路徑上不准再生圖元。

`ui/output_band.py`（243 行）整支刪掉。留著一個沒有呼叫者的畫圖模組，下一個
人會照著它再畫一個框。

## 2. ROUTE BY 收起來，不刪

使用者問能不能順便拿掉 pre-filter。**收起來而不是刪掉，因為那兩件事不是同
一件**：

| | 做什麼 |
|---|---|
| `route_by`（現有）| 不同 code 走**不同卡片組**（全部都跑，走不同路）|
| Input 的篩選（新）| **只有指定 code 的才跑**，其他的根本不進來 |

新的蓋不掉舊的。而「不同的 Classnumber 走不同的卡片」是使用者 2026-08-24
自己定調的需求 —— `CLAUDE.md` §5 那張表因此適用：**不確定的時候先收起來**。

⚠ **兩個入口同進同出**（`scope.SHOW_ROUTE_BY`）：畫布徽章與判定欄上方的編輯
區塊。只藏一邊的話，使用者仍然編得出一份會分流的 recipe，而畫布上一個字都
不會說 —— 那正是這個 repo 一直在消滅的「畫布說謊」。

既有的徽章測試**留著**，用 fixture 把開關扳開來跑（同 `SHOW_SAMPLE_ENTRIES`
那套辦法：機制還在，而且證明得出來還在）。

## 3. Input 的 code 篩選（新功能）

載入卡兩格可選參數（`only_column` ＋ `only_codes`），只跑 KLARF 某一欄符合
的那些 defect。

**「不跑」＝根本不進來**，套在 `batch.run_batch` 挑 items 那一行、早於任何一
張卡的 `run()`。那個選擇買到三件事：

* 不需要第三種結果狀態（不是 ok、也不是 error）→ CSV 的欄、bin 的統計、
  黃金值一個位元組都不用動；
* **被篩掉的那幾顆 KLARF 完全不會被改寫**；
* 兩格都空 = 嚴格附加，既有的每一份 recipe 一個位元都沒變。

**篩在 `limit` 前面。** 反過來的話「First 200」會先切掉一批再從裡面挑符合的
—— 使用者看到的是「我明明有 37 顆 code 2，怎麼只跑了 3 顆」。

**零顆符合時擋下來並講出是哪一個篩選。** 引擎那一頭篩得很乾淨，而乾淨的下場
正是危險的：一個打錯的欄名跑出來是「0 defects」與一張空表，而「資料沒載到 /
pipeline 壞了 / 篩選太緊」這三件事的下一步完全不同。

判準是 `Step.item_filter` 這個 hook，不是一份寫死的載入卡清單 —— 同 `scale`。

### ⚠ 一個自己抓到的更正：它**會**進快取簽章

第一版的測試斷言它**不該**進，理由是它不改任何一顆怎麼算 —— 推論是對的。
但簽章收的是那張卡的**每一個參數**（`carry` 也一樣，它也不改影像），要把某
一格排除掉就得發明一個「這一格不影響結果」的標記，而**標錯的下場是拿到上一
次設定算出來的影像**。

> **代價不對等**：進去最壞是改完篩選第一次跑比較慢；漏標最壞是跑得完、
> 有數字、而且是錯的。所以保守留著，而測試翻面守那個決定。

## 4. 判定收合成一張卡

使用者：「ADC 他一樣是張卡片，可以，但把它點開可以看到 decision tree。」

**這件事幾乎免費** —— 收合的能力 F24 §4 就做好了（雙擊入口卡切換），只是
預設是展開。於是畫布右邊常駐一整片菱形，而它跟左邊那一排卡片是兩種長得不
一樣的東西。翻過預設就是了（`canvas.TREE_COLLAPSED_DEFAULT`）。

⚠ **這是檢視狀態，不是 recipe 的內容**（同縮放平移）—— 存檔存不到它。
測試用 AST 掃 `toggle_tree_collapsed` 的**函式體**（不含 docstring），
擋「順手把它存進 recipe」。

**沒有做完整版**（`decide` 從頂層鍵搬進 `nodes`、`type="tree"` 參數、70 處
引用、遷移、黃金值重驗）—— 那是 F49-3，畫面上的差別是零。

## 5. 淡線：用名字吃的數字，來源看得見

F49 量過「讓特徵真的變成邊」的代價，結論是先不付。這一輪付**便宜的那一半**：
把來源畫出來，但它是**視圖不是邊**。

* 不進 `recipe.edges`、不影響 `execution_order`、不進快取簽章、拉不動剪不掉；
* **判定的菱形與卡片走同一支**（`tree_scene.ghost_wires`，從 F24 的
  `build_ghosts` 抽出來）—— 兩份會漂，而漂掉的那一份會讓畫布說謊；
* 來源從**宣告**推（`RecipeModel.feature_owners`）：卡片宣告會寫出那個數字，
  線才畫得出來。指到沒人算得出來的名字 → **一條線都不畫**（畫一條指向
  「不知道哪裡」的線比不畫更糟）。

⚠ **跟 F42 B4 拆掉的那條推導路不是同一回事。** 那裡的問題是**兩份相加**
（`edge_lines()` ＋ `region_lines()`，每條區域線被畫了兩次）；這裡只有一個
出處（那張卡的參數），線是它的投影。這句話寫在程式碼上，不然下一個人會照
F42 的結論把它清掉。

## 6. 判定的警告掛得上徽章

`Issue.node_id` 是「哪一張卡」，而判定不是一張卡 —— 它的 issue 一律
`node_id=None`，而 `studio._node_problems()` 第一件事就是把沒有節點的丟掉。
於是同樣是「指到一個沒人算得出來的數字」：

| | 卡片的特徵警告 | 判定的特徵警告 |
|---|---|---|
| 畫布徽章 | ✅ 一改就看得到 | ❌ 沒有 |
| 什麼時候講 | 改的當下 | **跑完之後**，狀態列尾巴一次 |

而 `_node_problems` 自己的說明寫著徽章為什麼存在：「那個知識以前只在按下
Run trial 的那一刻出現一次……而跑一次是好幾分鐘。」

⚠ **判準是 `recipe.DECISION_ISSUE_CODES`，不是「`node_id` 是 None」** ——
沒有節點的 lint 裡還有三條講分流、一條講整張圖，掛上來就是讓入口卡替別人的
問題背鍋。配一支**反向測試**（`test_decision_issue_codes.py`）：掃原始碼，
每一條 `node_id=None` 的 lint 都要被分類到，新加一條而忘了分類會紅 ——
不然它會安靜地掉回地上，就是這一輪在修的那個洞。

### 兩顆徽章是兩抄，而那是刻意的

`_NodeItem._paint_badge` 與 `_EntryItem._paint_badge` 幾何不同、import 方向
不同，共用一支要繞。所以留一張便利貼：**動一邊就要動另一邊**，而
`test_the_two_badges_are_drawn_the_same_way` 逐項比那幾個決定外觀的數字。

## 7. 驗收

* 核心 **2766 綠**、UI **逐檔全綠**、黃金值三份**逐項相同**；
* 新測試五支（腳帶 9、篩選 10、淡線 7、判定徽章 6、lint 分類 3）；
* **每一條新規矩都做過「把 bug 放回去 → 它變紅」**，其中兩次抓到自己：
  1. 「不准替別人背鍋」第一版**抓不到東西** —— 它只問被挑中的那條在不在表裡，
     而那個場景剛好只有判定的 lint。改成故意讓一條不是判定的 lint 更嚴重。
  2. 兩條測試掃原始碼時抓到**自己的註解／docstring**（墓碑註解與「不進
     recipe」那句話）。濾掉註解、用 AST 掃函式體。

> 兩次都是同一個形狀：**一條抓得到不存在的問題的測試，跟一條什麼都抓不到的
> 測試一樣沒用**（F26 §4 記過）。這一輪把它記成流程：新測試寫完就把 bug
> 放回去一次。
